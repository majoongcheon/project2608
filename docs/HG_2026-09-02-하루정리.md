## 1. 모델 개선 실험 여섯 개 — 전부 기각

| 시도 | 핵심 숫자 | 판정 |
|---|---|---|
| 문항 7 → 14개 | test F1 **+0.0004** · 판정 불가 0.0249 → 0.0420 (1.7배) | 폐기 |
| 정규화 튜닝 (15조합) | l2 C=10 이 +0.0200 이나 **t=1.63** · 3명짜리 계수 2배 | 기각 |
| 서열 모델 (예/아니오 4번) | F1 −0.0028 · 재현율 −0.0023 · 전부 t<1.9 | 기각 |
| 변수 7 → 38개 | 로지스틱 0.3141 · RF 0.2825 (기준 0.3364) | 기각 |
| 데이터를 더 모으면 (학습곡선) | 마지막 구간 **+0.7%p** < 폴드간 표준편차 2.9%p | 평평 |
| 라벨 재정의 (3구간·2분류) | 3구간 −0.1%p · 2분류 **+0.8%p** (기준 +2.0%p) | 기각 |

### 결과보다 중요한 것 — 재는 방식

여섯 번 모두 **판정 기준을 돌리기 전에 적어 두고** 시작했다. 결과를 보고 기준을 옮기면
실험이 아니라 사후 합리화가 된다.

5개 폴드에서 95% 로 "우연이 아니다" 라고 말하려면 **|t| ≥ 2.776** 이 필요한데,
**여섯 번 중 이를 넘긴 실험이 하나도 없다.** 좋아 보였던 것들은 전부 폴드 하나가 끈 것이었다.

그 밖에 지킨 규칙 — `cv_fold` 로 고정된 5-fold 만 사용 · test 602건 미사용 ·
짝지어 비교 · 결정 가중치를 유리하게 고르지 못하게 고정 또는 재현율 맞춤 ·
한 번에 한 가지만 변경 · 스냅샷만 읽고 배포본·DB 미접근.

## 2. 왜 안 되는지 — 원인을 찾았다

```
라벨은 멀쩡하다            상식 방향으로 붙는다. help_needed_hours r = +0.442
                          (배포 문항 4개는 선택지 문구까지 대조해 방향 확인)

그런데 같은 답에서 갈린다   7문항 기준 2명 이상인 조합의 80.1% 에서 라벨이 갈리고,
                          62.9% 는 고부담이냐 아니냐에서조차 갈린다

변수를 늘려도 안 오른다     38변수를 다 넣어도 7문항과 같은 자리
데이터를 늘려도 안 오른다   384건 → 1,918건 동안 66.9% → 69.4%
```

세 개를 합치면 이렇게 된다.

> **라벨이 망가진 것도 아니고, 문항이 모자란 것도 아니다.
> 이 설문 도구로 설명되는 부담의 몫이 원래 작다.**

부담은 당사자의 상태만으로 정해지지 않는다. 보호자 본인의 건강, 소득과 활동지원 급여,
실제 돌봄 시간, 형제자매의 분담, 거주지의 서비스 접근성 — **이 설문에 없는 것들**이
크게 작용한다. 이건 분석으로 만들 수 없고 다음 조사에서 문항으로 넣어야 나온다.

C  다음에 무엇을 하면 되는지 기관 연락 시 이 화면을 보여줘도 된다 / 같은 답이면 결과도 같다
