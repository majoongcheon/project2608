# 추론 경로가 정말 파이썬으로 연결되었는가 — 5회 확인

**작성** 오현근 세션 · 2026-09-02 13:2x
**질문** 옛 방식(백엔드가 직접 계산)으로 조용히 돌고 있는 것은 아닌가?
**결론** **아니다. 판정은 파이썬이 한다.** 폴백 경로가 물리적으로 존재하지 않고,
파이썬을 끄면 판정이 나오지 않으며, 파이썬 쪽 파일만 바꾸면 결과가 따라 바뀐다.

의심할 만한 질문이었다. 2026-09-02 오전에 **프론트만 새 코드로 넘어가고 백엔드는 전날
프로세스로 남아 아무 오류 없이 화면이 비는** 사고가 있었기 때문이다. "코드를 고쳤다"와
"그 코드가 실제로 돌고 있다"는 다른 말이다.

---

## 1차 — 폴백 경로가 코드에 남아 있는가

| 확인 | 결과 |
|---|---|
| `src/inference/predictor.ts` | **없음** (삭제됨) |
| `src/inference/undecidable.ts` | **없음** (삭제됨) |
| `tests/parity/` | **없음** (삭제됨) |
| 백엔드에 확률 계산 코드 | **없음** — `softmax`·`Math.exp`·`predictProba` 어디에도 없다 |
| `CB_INFERENCE` 스위치·if/else 폴백 | **없음** |
| 판정을 받는 곳 | `callInference` 하나뿐 (`diagnosisService.ts:103`) |

`eventService.ts` 에 `isUndecidable` 이 나오지만 이건 **DB 에 기록하는 필드 이름**이지
계산이 아니다.

> **백엔드는 판정을 계산할 능력 자체가 없다.** 돌아갈 옛 경로가 존재하지 않는다.

---

## 2차 — 지금 도는 프로세스가 정말 그 코드인가

오전 사고가 정확히 이 지점이었다. 파일을 고쳐도 프로세스가 옛것이면 소용없다.

```
백엔드 프로세스 시작 : 2026-09-02 13:06:34
diagnosisService.ts  : 2026-09-02 13:06:03   ← 프로세스가 더 나중
inferenceClient.ts   : 2026-09-02 12:59:09
```

기동 로그도 파이썬에 붙었다고 말한다.

```
추론 서비스 : unix:/Users/pioneer3/project2608/run/cb-inference.sock · v1.0.0
```

파일이 커밋 이후 누군가에게 바뀌지 않았는지도 확인했다.

```
diagnosisService.ts : 커밋과 동일 (sha 일치)
inferenceClient.ts  : 커밋과 동일 (sha 일치)
git status backend/src/ : 변경 없음
```

## 3차 — 파이썬이 없으면 정말 못 하는가

폴백이 숨어 있다면 파이썬을 죽여도 결과가 나올 것이다.

| 상태 | 결과 |
|---|---|
| 파이썬 살아 있음 | 구간 **중간부담군** · unavailable=False |
| **파이썬 죽임** | 구간 **없음** · unavailable=**True** |
| 파이썬 되살림 | 구간 **중간부담군** · unavailable=False |

공개 사이트(`https://p3.sumzip.com`)로 요청해 확인했다.

> **파이썬이 없으면 판정이 나오지 않는다.** 백엔드가 몰래 대신 계산하지 않는다.

---

## 4차 — 요청할 때 파이썬이 실제로 일하는가

살아 있기만 하고 실제 계산은 다른 데서 할 수도 있다. 파이썬 프로세스의 CPU 시간을 쟀다.

```
진단 30건 보내기 전 : 0:05.30
30건 보낸 뒤        : 0:05.36     ← 60ms 증가 (건당 약 2ms)
```

> **요청할 때마다 파이썬이 CPU 를 쓴다.** 놀고 있는 게 아니다.

소켓 연결은 `lsof` 로 못 잡았다. 요청 하나가 2ms 만에 열고 닫혀 관측 주기보다 짧기 때문이다.
연결을 유지하지 않는 설계라 정상이다.

---

## 5차 — 파이썬 쪽 모델만 바꾸면 결과가 따라 바뀌는가

가장 결정적인 시험이다. **파이썬이 읽는 파일만** 바꾸고 백엔드는 손대지 않았다.

빈도표(`freq_table`)를 비운 대체 릴리스를 만들었다. 그러면 모든 응답이 "처음 보는 값"이
되어 희소성이 최저가 되고 **판정 불가**가 나와야 한다.

판정 불가는 기관 안내가 함께 나가는 **안전한 출력**이라, 잘못된 구간을 이용자에게 보여줄
위험이 없다. 그래서 이 방식을 골랐다.

| 파이썬이 읽는 릴리스 | 공개 사이트의 답 |
|---|---|
| 정상 (`models/`) | 구간 **중간부담군** · 판정불가 문구 없음 |
| **대체 (빈도표 비움)** | 구간 **없음** · 판정불가 문구 **있음** |
| 정상 복귀 | 구간 **중간부담군** · 판정불가 문구 없음 |

> **파이썬이 읽는 파일을 바꾸자 웹사이트의 답이 바뀌었고, 되돌리자 원래대로 왔다.**
> 결과가 파이썬에서 온다는 직접 증거다.

시험이 끝난 뒤 대체 릴리스는 지웠고, 서비스는 정상 릴리스로 돌아와 있다.
