## 0. 쉽게 말하면

지금 모델은 다섯 구간을 **서로 무관한 것처럼** 다룬다. 사과·배·감·귤·포도 중 하나를
고르듯이. 그런데 부담 수준에는 **순서가 있다.**

```
1 최고부담  >  2 고부담  >  3 중간  >  4 저부담  >  5 부담없음
```

최고부담을 **고부담**으로 틀리는 것과 **저부담**으로 틀리는 것은 전혀 다른 잘못인데,
지금 모델은 둘을 똑같이 취급한다.

**순서를 아는 모델로 바꿔 보자**는 것이 이 실험이다.

---

## 1. 무엇을 만드나

"다섯 중 하나 고르기"를 **"네 번의 예/아니오"** 로 바꾼다.

```
질문 ①  최고부담인가?          →  P(y ≤ 1)
질문 ②  고부담 이상인가?        →  P(y ≤ 2)   ★ 서비스가 원하는 값
질문 ③  중간 이상인가?          →  P(y ≤ 3)
질문 ④  저부담 이상인가?        →  P(y ≤ 4)
```

네 답을 빼면 다섯 구간 확률이 나온다.

```
P(최고부담) = P(y≤1)
P(고부담)   = P(y≤2) − P(y≤1)
P(중간)     = P(y≤3) − P(y≤2)
P(저부담)   = P(y≤4) − P(y≤3)
P(없음)     = 1 − P(y≤4)
```

---

## 2. 왜 나을 수 있나

### ① 데이터를 더 많이 쓴다

지금은 2,398건을 다섯 구간에 나눠 쓴다. 특히 **5번 구간은 61건뿐**이다.
서열 모델은 **매 질문마다 2,398건을 통째로** 쓴다.

### ② 순서를 안다

실제 응답 시험에서 나온 오류 구성이다.

```
정확히 맞음   48.7%
한 칸 빗나감  41.4%   ← 겨냥하는 곳
두 칸 이상     9.9%
```

### ③ 고부담 확률을 직접 학습한다

`P(y≤2)` 가 곧 고부담 확률이다. 지금은 다섯 확률을 구한 뒤 두 개를 더하는데,
서열 모델은 **그 값 자체를 최적화**한다. SC-005(재현율 0.70)를 정면으로 겨냥한다.

---

## 3. 미리 알고 있는 난관

### 3.1 네 질문의 난이도가 다르다

| 질문 | 예 | 아니오 | 예의 비율 | |
|---|---|---|---|---|
| P(y≤1) | 371 | 2,027 | 15.5% | 치우침 |
| **P(y≤2)** | 1,303 | 1,095 | **54.3%** | **균형 — 가장 잘 배울 것** |
| P(y≤3) | 2,035 | 363 | 84.9% | 치우침 |
| **P(y≤4)** | 2,337 | 61 | **97.5%** | **극단 — 사실상 답이 정해짐** |

**P(y≤4) 는 "5번 구간이 아닌가"를 묻는 것**인데 5번이 61명뿐이라, 모델이
"거의 항상 예"라고 답할 것이다. 결과적으로 **P(부담없음) ≈ 0** 이 된다.

지금 모델도 5번을 거의 예측하지 않으므로(587건 중 1건) **나빠지는 것은 아니다.**
다만 개선도 없다.

### 3.2 단조성 위반

네 모델이 따로 학습하므로 `P(y≤2) < P(y≤1)` 같은 모순이 생길 수 있다.
그러면 빼기에서 **음수 확률**이 나온다.

**대응** — 누적 최대값으로 순서를 강제하고(`np.maximum.accumulate`), 남는 음수는 0으로
자른 뒤 합이 1이 되게 정규화한다. **위반 빈도를 세어 기록한다** — 자주 생기면 그 자체가
기각 사유다.

### 3.3 결정 규칙을 정해야 한다

서열 모델에는 두 가지 방식이 있다.

| 방식 | 내용 |
|---|---|
| **A. 재구성 후 기존 규칙** | 5구간 확률로 되돌린 뒤 지금처럼 `확률 × 결정 가중치` 의 최대 |
| B. 임계 방식 | `P(y≤k) > 0.5` 인 가장 작은 k |

**A 로 간다.** 지금과 같은 규칙을 써야 공정한 비교가 되고, 결정 가중치도 그대로 쓸 수 있다.
B 는 가중치를 적용할 자리가 없어 SC-005 를 겨냥하기 어렵다.

## 4. 어디에 코드를 넣나

**파이프라인은 건드리지 않는다.** 실험 스크립트 하나로 먼저 한다.

```
ml/HG_ordinal.py     ← 새로 만들 것. 학습·교차검증·비교를 이 안에서
```

`_core.cv_scores` 는 5클래스를 가정하므로, 서열용 교차검증은 스크립트 안에 따로 쓴다.
`_core.make_logit`·`decide`·`macro_f1`·`high_burden_recall` 은 그대로 재사용한다.

**좋은 결과가 나온 뒤에야** `stages/` 에 정식으로 넣는다.
정규화 때처럼 파이프라인부터 고치면 결과가 나쁠 때 되돌릴 것이 많아진다.

## 5. 판단 기준 — **실행 전에 못박는다**

정규화 때 사후에 판단하느라 애매했다. 이번에는 먼저 정한다.

### 5.1 "다음 단계로 갈 만한가" 기준 (실험 결과로 판단)

| 지표 | 지금 (train 5-fold) | 조건 |
|---|---|---|
| **고부담 재현율** | 0.7844 | **이상** — 가장 비싼 지표 |
| **두 칸 이상 오류** | 9.0% | **이하** — 서열 모델의 존재 이유 |
| macro F1 | 0.3364 | **떨어지지 않을 것** |
| 단조성 위반 | — | 전체의 **5% 미만** |

**넷 중 하나라도 못 넘으면 기각**하고 기록만 남긴다.

### 5.2 통계적 근거의 한계를 미리 인정한다

5폴드로는 작은 차이를 가려낼 수 없다. 정규화 실험에서 관측된 폴드별 편차(±0.0275)로
계산하면 이렇다.

| 기준 | 필요한 최소 차이 |
|---|---|
| t ≥ 2 (p≈0.12) | +0.0246 |
| **통상적 95% 유의수준** (t≥2.78, 자유도 4) | **+0.0341** |

**"5폴드 중 4승"은 동전을 던져도 18.8% 확률로 나온다.** 처음 계획에 이 기준을 넣었으나
근거로 쓸 수 없어 뺐다.

따라서 이 실험은 **"유의미한 개선을 증명한다"가 목표가 아니다.**
**"방향이 맞는지 보고, 맞으면 더 볼 값어치가 있는지 판단한다"** 가 목표다.

정말 증명하려면 반복 교차검증(5-fold × 여러 시드)이 필요한데, 그건 `cv_fold` 를 새로
만드는 것이라 **원칙 IV(고정 분할)와 충돌**한다. 하지 않는다.

## 6. 비교 방법

정규화에서 배운 대로 처음부터 **같은 폴드끼리** 비교한다.

- 결정 가중치는 **배포본 값으로 고정** (공정 비교)
- 폴드별 값을 전부 기록. 평균만 보지 않는다
- 두 칸 이상 오류는 **폴드별로 따로** 센다

## 9. 채택하려면 무엇을 더 해야 하나 ★

**이 실험은 여기까지가 아니다.** 기준을 통과해도 바로 배포할 수 없다.
처음 계획에 이 비용이 빠져 있었다.

### 9.1 기여 요인 분해를 새로 정의해야 한다 — 가장 큰 문제

지금 분해기는 **계수 행렬 하나**를 전제한다.

```python
# explain/saabas.py
actual = model['coef'][cls][model['spans'][j][0] + idx]
base   = model['intercept'][cls] + sum(e[cls] for e in model['expected_contrib'])
```

서열 모델은 **계수 뭉치가 네 개**다. "이 답변이 중간부담군 판정에 얼마나 기여했나"를
어떻게 계산할지 **정의 자체가 없다.**

FR-011 이 기여 요인 표시를 요구하므로 건너뛸 수 없다. 생각할 수 있는 방법은 셋이다.

| 방법 | 문제 |
|---|---|
| 인접 두 모델의 계수 차 | 재구성 확률이 차이라서 원리상 맞지만 검증이 필요 |
| SHAP | 의존성이 늘고 요청마다 계산이 느리다 |
| `P(y≤2)` 모델의 기여만 제시 | 고부담 여부만 설명하게 된다. 스펙과 어긋난다 |

**셋 다 반나절 이상 걸린다.**

### 9.2 판정 불가 임계값을 반드시 재보정해야 한다

지금 `tau_conf = 0.3239` 는 **이 모델의 확률 분포**에서 뽑은 값이다.
서열 재구성은 인접 누적확률의 **차**라서 값이 더 잘게 쪼개지고, 최대확률이 낮아지기 쉽다.

모의 계산 결과다.

| 최대확률이 | 판정 불가 비율 |
|---|---|
| 지금 | 2.00% |
| 15% 낮아지면 | **10.97%** |
| 25% 낮아지면 | **29.27%** |

**SC-016(10% 이하)을 바로 위반한다.** `calibrate` 재실행이 필수다.

### 9.3 아티팩트 구조와 검증기가 바뀐다

| 파일 | 무엇이 바뀌나 |
|---|---|
| `stages/export.py` | 계수 뭉치 네 개를 어떻게 담을지 |
| `artifacts/validate.py` | 새 구조를 검증 |
| `serve/engine.py` | `predict_proba` 하나가 아니라 네 번 호출 후 재구성 |
| `explain/saabas.py` | 9.1 참조 |
| 골든 케이스 | 확률이 달라지므로 새로 만들어야 함 |

### 9.4 그래서 결과에 따라

| | 다음 |
|---|---|
| **기준 통과** | **바로 채택하지 않는다.** 9.1~9.3 의 비용(최소 하루)을 팀과 상의한 뒤 결정 |
| **부분 통과** | 기록 남기고 보류. 발표 근거로 사용 |
| **기각** | 기록만 남김. "서열 모델도 해봤다"가 근거가 된다 |

## 10. 두 칸 이상 오류를 정말 줄일 수 있나 — 미리 본 것

계획을 세우고 나서 **겨냥하는 오류가 어떤 것인지** 먼저 확인했다.

```
지금 오류 구성 (train 교차검증 2,398건)
  0칸  46.3%   1칸  44.0%   2칸  9.0%   3칸  0.7%   4칸  0.04%
```

두 칸 이상 오류 234건의 내역이다.

| 실제 → 예측 | 건수 |
|---|---|
| 저부담 → 고부담 | 84 |
| 고부담 → 저부담 | 44 |
| 최고부담 → 중간 | 44 |
| 부담없음 → 중간 | 25 |
| 중간 → 최고부담 | 17 |
| 나머지 | 20 |

**5번(부담없음)이 관련된 것은 35건(15%)뿐이다.** 나머지 199건은 저부담↔고부담을
오가는 것이라, **서열 모델이 겨냥할 여지가 실제로 있다.**

3.1 에서 P(y≤4)가 사실상 못 배운다고 했는데, 그것이 두 칸 오류의 대부분을 차지하지
않는다는 뜻이다. **이 실험을 할 이유가 데이터로 확인됐다.**

## 12. 5회 검토에서 고친 것

계획을 쓴 뒤 다섯 번 서로 다른 관점으로 다시 읽었다. **결함 넷을 찾았다.**

### 1차 — 판단 기준이 통과 가능한 수준인가

**결함** — "5폴드 중 4승 이상"을 macro F1 기준으로 넣었는데, **동전을 던져도 18.8%
확률로 나오는 값**이었다. 근거로 쓸 수 없다.

**조치** — 그 기준을 빼고 "떨어지지 않을 것"으로 바꿨다. 대신 5.2 를 새로 써서
**5폴드로는 작은 차이를 증명할 수 없다는 한계를 미리 밝혔다.**
실험 목표도 "증명"이 아니라 "방향 확인"으로 낮췄다.

### 2차 — 채택되면 실제로 무엇을 고쳐야 하나

**결함** — **기여 요인 분해를 어떻게 할지 계획에 아예 없었다.**
`saabas._logit_contrib` 은 계수 행렬 하나를 전제하는데 서열 모델은 네 뭉치다.
FR-011 이 기여 요인을 요구하므로 건너뛸 수 없는데, 이 비용이 빠져 있었다.

**조치** — 9.1 을 신설해 방법 세 가지와 각각의 문제를 적었다. **전부 반나절 이상**이다.

### 3차 — 판정 불가 임계값은 어떻게 되나

**결함** — "재보정 필요"라고만 적고 얼마나 심각한지 재보지 않았다.

**조치** — 모의 계산했다. 최대확률이 **15% 낮아지면 판정 불가가 2% → 11%**,
25% 낮아지면 **29%** 가 된다. **SC-016(10% 이하)을 바로 위반한다.**
9.2 에 수치와 함께 적었다.

### 4차 — 겨냥하는 오류가 정말 줄어들 수 있나

**확인 결과 — 좋은 소식이다.** 두 칸 이상 오류 234건 중 **5번(부담없음)이 관련된 것은
35건(15%)뿐**이다. 나머지 199건은 저부담↔고부담을 오가는 것이라 서열 모델이 겨냥할
여지가 있다.

3.1 에서 P(y≤4)가 사실상 못 배운다고 했는데, **그것이 두 칸 오류의 대부분이 아니다.**
10장에 근거를 적었다.

**부수 정정** — 두 칸 이상 오류를 "9.9%"로 적었는데 그건 test 값이었다.
train 교차검증 기준은 **9.0%** 다. 기준표를 고쳤다.

### 5차 — 스펙 준수와 빠진 것
