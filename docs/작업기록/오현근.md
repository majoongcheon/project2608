## 1. 발표에 바로 쓸 수 있는 세 가지

### ① "왜 정확도가 48%인가" — 데이터로 답했다

가장 나올 만한 질문이다. **정답을 가리고 군집화**해서 답을 만들었다.

| 지표 | 실측 | 뜻 |
|---|---|---|
| 실루엣 계수 | **0.12** | 0.25 미만 = 뚜렷한 덩어리 구조 없음 |
| 부담 구간과 일치도 (ARI) | **0.027** | 0에 붙음 = 거의 무관 |
| PCA 1번 성분 | **12.9%** | 데이터를 관통하는 축이 없음 |
| 자연스러운 군집 수 | **2개** | 5개가 아니다 |

> **설명변수가 돌봄부담을 5구간으로 가를 만큼의 정보를 담고 있지 않다.**
> 알고리즘을 바꿔도 크게 오르지 않는다.

같은 모델로 문제만 "고부담이냐 아니냐"로 바꾸면 **정확도 0.478 → 0.696** 으로 오른다.
데이터가 자연스럽게 나뉘는 수(2)와 서비스가 실제로 필요한 판정이 일치한다.

### ② "왜 최신 알고리즘을 안 썼나" — 붙여봤더니 졌다

| 알고리즘 | macro F1 | |
|---|---|---|
| **다항 로지스틱 회귀** | **0.318** | 채택 |
| 랜덤 포레스트 | 0.289 | |
| 엑스트라 트리 | 0.267 | |

**단순한 방법이 이겼다.** 학습 데이터가 2,398건뿐이라 복잡한 모델은 외워버리고,
①에서 확인했듯 애초에 복잡한 구조가 없었다.

### ③ 성능을 한 문장으로

> 다섯 구간을 정확히 집어내지는 못하지만(**정확도 47.8%**), **"지원이 필요한 사람인가"는
> 69.6% 정확도**로 가려낸다. 실제 고부담 보호자의 **77.3%** 를 잡아내고,
> 부담 큰 사람을 "부담 없음"으로 판정하는 **위험한 실수는 test 602건 중 0건**이다.

## 2. 모델 검증 — 전수 확인

### 학습·평가 절차 확인

- 분할이 **Stratified K-Fold** 임을 폴드별 구성으로 검증 (폴드 간 편차 **0.20%p**)
- 층화가 필요했던 이유 규명 — `부담없음` 이 61건(2.5%)뿐이라 무작위 분할이면 폴드마다
  8~17건으로 흔들리고 macro F1 이 튄다
- 분할이 코드가 아니라 **DB 컬럼(`split`·`cv_fold`)에 고정**돼 있음을 확인 (재현성)

### 혼동행렬

| | 교차검증 | test |
|---|---|---|
| 정확도 | 0.4629 | **0.4784** |
| 고부담 재현율 | 0.7843 | **0.7730** |
| 고부담 정밀도 | 0.6934 | **0.6981** |
| 폴드 간 편차 | 0.044 | — |

**test 가 교차검증보다 높다** — 과적합이 심하지 않다는 건강한 신호다.

읽어낸 것 네 가지:
- 답이 "고부담군"으로 몰린다 → 결정 가중치 1.1 의 의도된 효과
- 최고부담군을 한 칸 내려 판정하는 경우가 많다 → 둘 다 즉시 안내 대상이라 실질 피해 작음
- `부담없음`(61건)은 거의 못 맞힌다 → 서비스 개입 대상이 아니라 영향 작음
- **정반대 오류는 없다** → 가장 위험한 실수가 일어나지 않음

## 3. 문항 수 실험 — 7 vs 14

7문항이 적어 보인다는 우려에서 출발해 **14문항 모델을 실제로 만들어 비교**했다.

| | 7문항 `v1.0.0` | 14문항 `v1.1.0` |
|---|---|---|
| test macro F1 | 0.3416 | 0.3420 |
| test 고부담 재현율 | **0.7730** | 0.7669 |
| **test 판정 불가** | **2.49%** | **4.20%** |

**성능은 같은데 판정 불가만 1.7배 늘었다.** 문항을 두 배로 늘려 응답 부담과
결과를 못 받는 사람만 늘리고 정확도는 얻지 못했다 → **7문항 유지로 결정.**

원인도 규명했다 — 14문항에 들어온 **나이 변수 2개**가 희소성 점수를 끌어내렸다
(`caregiver_age` 78레벨, 평균 log p −3.782 / 나머지 문항은 −0.47~−1.59).

**후속 실험** — 나이를 구간화하면 해결되는지 시험했다. 희소성 지표는 개선됐지만
(평균 rarity −1.466 → −1.239, 원-핫 224 → 100열) **판정 불가 비율은 그대로**였다.
보정 단계가 임계값을 자동으로 맞추기 때문이며, **3% 는 데이터가 아니라 규칙이 겨냥한
목표값**이라는 사실을 알아냈다. 재현율은 오히려 떨어져 채택하지 않았다.

## 4. 판정 불가 규명 — 가설 4개 중 3개 기각

"판정 불가가 너무 자주 뜬다"에서 출발해 원인을 하나씩 확인했다.

| 가설 | 검증 방법 | 결과 |
|---|---|---|
| 확률 보정이 안 돼서 | 신뢰도 곡선·ECE | **기각** — ECE 0.042 로 이미 잘 보정됨 |
| margin 기준이 더 정확 | 같은 인원으로 통일해 비교 | **기각** — 현재 max 기준이 나음 (0.611 vs 0.569) |
| 문항 수 때문 | 나이 구간화 재학습 | **기각** — 임계값이 자동 보정됨 |
| **배포 설정이 틀림** | DB 설정 vs 모델 산출물 대조 | **적중** → 5장 |

**5~10분짜리 확인으로 반나절씩 걸릴 구현 세 건을 아꼈다.**

### 판정 불가 48명의 정체

- 1등·2등 확률 격차 **0.021** (정상 판정은 0.191) — 사실상 동점
- 응답이 "긍정적" 극단에 몰려 있는데(일과 매우 좋아함 41.7% vs 전체 9.3%)
  **실제로는 46%가 고부담군** — 응답과 실제가 어긋나는 사람들
- 억지로 답을 주면 **27%만 맞는다** (전체 46%)

> **판정 불가는 결함이 아니라 데이터의 한계를 정직하게 드러낸 결과다.**

### 화면 설계 (미구현)

"가까운 구간이라도 알려주자"는 안을 검토했으나 **실측으로 기각**했다 —
이 집단의 2단계 정확도가 **0.542** 인데 아무에게나 "큰 쪽"이라 답하기가 **0.543** 이다.
모델이 가진 정보가 없다.

대신 **추측이 아닌 사실만** 알려주는 두 유형 화면을 설계했다.

| 유형 | 인원 | 알려줄 사실 |
|---|---|---|
| A 드문 응답 | 24명(1%) | 어느 답이 조사 자료의 몇 % 인지 + "응답이 잘못된 것이 아닙니다" |
| B 확신 부족 | 48명(2%) | 답한 내용 요약 (상담 갈 때 그대로 활용) |

제목을 "판단할 수 없습니다"에서 **"이번에는 상담을 권해드립니다"** 로 바꿔
실패 통지가 아닌 대안 제시로 만든다. **2026-09-02 에 이어서 진행.**

| 설정 | 배포되던 값 | 실제 산출값 |

발동하지 않았다.** 스펙이 설계한 두 축 중 하나가 죽어 있었다.

**영향** — 판정 불가 83명(3.46%) → 72명(3.00%), 기여 요인 강약 구분 복구.

**근본 원인은 사람 실수가 아니라 작업 정의의 구멍이었다.** `T015`(설정 시드)가
모델보다 먼저 도는 구조인데 학습 후 재실행하라는 지시가 없었다.

- `db/seeds/config.js` — 숫자를 손으로 적는 대신 `models/*.json` 에서 **직접 읽도록** 변경.
  재학습하고 시드만 돌리면 값이 자동으로 따라온다
- `tasks.md` — **T029a 신설** (설정 반영 + 백엔드 재기동). 의존 그래프와

### 오늘 만든 것 — 판정 불가 갈림길 회귀 테스트

`diagnose()` 를 통째로 돌려 **판정 / 판정 불가 두 갈래가 섞이지 않는지** 잠근다.

| 갈래 | 확인 |
|---|---|
| 판정된 응답 | 부담 구간·기여 요인·비교가 나오고 **`undecidable` 이 null** |
| 판정 불가 (양쪽 유형) | 부담 구간·기여 요인·비교·2인 보정 안내가 전부 null, 근거 목록은 여기서만 |
| 유형별 차이 | `sparse` 는 비율이 숫자, `ambiguous` 는 전부 null + 문항 수만큼 순서대로 |
| 문구 누수 | 안내문 JSON 안에 "최고부담군" 등 **구간 명칭이 한 글자도 없음** |

입력은 손으로 박지 않고 `models/parity_v1.json` 3,000건에서 갈래별 실제 응답을 골라 쓴다.
값을 고정하면 재학습 후 그 응답이 다른 갈래로 옮겨가 엉뚱한 이유로 깨진다.

**검출력을 실제로 확인했다** — 통과만으로는 울타리 역할의 증거가 되지 않아 코드를 일부러 망가뜨렸다.

| 변이 | 잡혔나 |
|---|---|
| 판정돼도 안내문을 조립하도록 변경 | ✅ `★ 근거 목록을 내지 않는다` 실패 |
| 판정 불가에도 기여 요인을 계산하도록 변경 | ✅ 양쪽 유형 `기여 요인과 비교를 내지 않는다` 실패 |

원본과 `diff` 로 차이 없음을 확인해 되돌렸다.

## 18:00 — main 을 받아 왔다 (머지)
