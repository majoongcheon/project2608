## 3. 설계 결정

### 3-1. 앙상블에 넣을 모델 — 계열을 흩는다

앙상블의 이득은 모델을 많이 넣어서가 아니라 **서로 다르게 틀리는 모델**을 섞어야 나온다.

| 모델 | 계열 | 설정 |
|---|---|---|
| `logit` | 선형 (다항 로지스틱) | one-hot, `max_iter=2000` — 현 배포본 `v1.0.0` 이자 기준선 |
| `rf` | 배깅 | 180그루, `max_depth=14`, `min_samples_leaf=8`, `max_features=sqrt` |
| `lgbm` | 부스팅 (리프 우선) | 400회, `lr=0.05`, `num_leaves=15`, 범주형 네이티브 |
| `xgb` | 부스팅 (깊이 제한) | 400회, `lr=0.05`, `max_depth=4`, one-hot |
| `catboost` | 부스팅 (타깃통계) | 400회, `lr=0.06`, `depth=5`, 범주형 처리 |

**제외 2종** — `ExtraTrees` 는 `rf` 와 오차가 겹쳐 새 정보를 주지 못한다. `HistGradientBoosting`
은 `lgbm` 과 사실상 같은 알고리즘인데 혼자 **280초**를 먹어 반복 CV 를 불가능하게 만든다.

**결합 방식 4종** — 소프트보팅(전체) · 소프트보팅(선형+부스팅3) · 가중 소프트보팅(가중치를 내부
CV 로 학습) · 스태킹(확률 25열 → 메타 로지스틱, 내부 CV 로 누수 차단).

### 3-2. 기존 벤치마크에서 발견한 채점 편향

`ml/SJH-model-benchmark.py` 의 `score()` 는 `tune_weights(P, y)` 로 클래스 가중치를 고른 뒤
**같은 `P`·`y` 위에서 그 가중치를 채점한다.** 보고된 `macro_f1_weighted` 는 모두 자기가
최적화한 대상 위의 값이다.

낙관 편향의 크기가 모델마다 다르므로(확률이 넓게 퍼진 모델일수록 튜닝 이득이 크다)
**모델 간 비교로는 쓸 수 없다.** logit 0.3383 과 xgb 0.3329 의 0.005 차이는 이 편향과
폴드 잡음 안에 묻힌다.

**대응** — 클래스 가중치를 fold 의 **학습 부분에서만** 고르고 검증 부분에 적용한다.
그리고 점수 하나가 아니라 **반복 CV 로 짝지은 차이 + 95% 구간**으로 보고한다.

```
soft-vote(전체)  −  logit :  -0.0112  [95% -0.0294, +0.0071]   → 차이 없음
stacking         −  logit :  +0.0203  [95% +0.0041, +0.0365]   → 실제 개선
```

### 3-5. 안 돌리고 얻은 것 — 고부담 정밀도 역산

14:37 의 **"이미 sjh 모델 비교에 다 있지않아??"** 가 불필요한 실행을 막았다.
맞는 지적이었다. 기존 파일에 `binary_accuracy` 와 `hb_recall` 이 이미 있어서,

```
TP = p·재현율 · FN = p − TP · TN = 이진정확도 − TP · FP = (1−p) − TN
```

이렇게 뽑은 7문항 표에서 배포본이 재현율 0.784 · 정밀도 0.693 으로 이진 F1 1위였다.
**본 실험(0.756 / 0.700)과 방향이 같다** — 역산이 맞았음을 사후 확인한 셈이다.

## 5. 결과 — 앙상블은 정말 졌다

train 2,398건 · 7문항 · 5회 반복 × 5-fold · 부트스트랩 2,000회 · 33분.
**test 602건은 열지 않았다.**

| 구성 | macro F1 차이 | 판정 |
|---|---|---|
| 소프트보팅(선형+부스팅3) | −0.0061 | 차이 없음 (잡음) |
| 가중 소프트보팅 | −0.0111 | 낮은 쪽이나 미확정 |
| 소프트보팅(5종) | −0.0136 | **실제로 낮음** |
| 스태킹 | −0.0353 | **실제로 낮음** |

**이긴 구성이 하나도 없다.** 8개 전부 구간 상한이 +0.006 이하다.
기준선 자신의 분할 간 표준편차가 **0.0049** — 쫓던 차이가 잡음과 같은 크기였다.

### 예상이 빗나간 곳 둘 (정직하게 남긴다)

1. **채점 편향은 범인이 아니었다.** 걷어내도 배포본은 0.3383 → 0.3348 로 거의 그대로였다.
   다만 걷어냈기에 "차이가 잡음"이라고 **말할 근거**가 생겼다.
2. **"앙상블이 재현율을 떨어뜨린다"는 해석은 허상이었다.** 역산 표에서 보이던 패턴이

### 유일한 예외

**스태킹만 지표에 따라 반대를 가리킨다** — macro F1 은 꼴찌(−0.0353)인데 고부담

## 7. 인코딩 실험 — 처음으로 이긴 구성

15:30 의 **"데이터트랜스폼을 하면 어떨까"** 에서 시작했다. 확인해 보니
`cb_feature_meta_v1.var_scale` 이 38변수 전부의 척도를 기록하고 있는데
**파이프라인이 한 번도 참조하지 않고 있었다.** 7문항 중 4개가 순서형인데
배포본은 전부 one-hot 으로 넣어 순서를 버린다.

모델을 로지스틱 하나로 고정하고 인코딩만 6가지로 바꿔 같은 절차로 비교했다.

| 인코딩 | 열 | macro F1 | 고부담 F1 | 판정 |
|---|---|---|---|---|
| onehot (배포본) | 53 | 0.3337 | 0.7258 | 기준 |
| thermo | 51 | 0.3334 | 0.7254 | 차이 없음 |
| collapse | 38 | 0.3342 | 0.7280 | 차이 없음 |
| **scale+collapse** | **26** | 0.2839 | **0.7362** | **고부담 F1 +0.0104 — 두 구간 모두 0 배제** |

**이 세션에서 배포본을 이긴 첫 구성이다.** 고부담 재현율도 0.755 → 0.777 로 올랐고
두 구간 모두 0을 배제한다. 대신 macro F1 은 0.334 → 0.284 로 확실히 낮다.
모델 크기는 모수 265 → 130 으로 절반이 된다.

### 빗나간 예측 셋 (하나만 맞았다)

1. **"다이얼을 줄이면 나아진다"** — 절반만 맞았다. 고부담 탐지는 올랐고 macro F1 은 크게 내렸다
2. **"`last_job_quit_reason` 15수준이 제일 심하다"** — **틀렸다.** 그 효과만 분리한
   `collapse` 는 세 지표 전부 차이가 없었다. L2 벌점이 이미 눌러 두고 있었다
3. **"누적 더미가 최선의 절충안"** — **틀렸다.** one-hot 과 사실상 완전히 같았다(±0.0007)

**맞은 것 하나** — 순서형을 순서로 넣는 것만이 효과를 냈다. 효과의 출처가 하나로 좁혀졌다.
