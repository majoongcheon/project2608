# 팀원별 작업 기록

발표 시 **팀원별로 한 일을 나눠 정리해 포함**하기 위한 기록이다.

## 왜 따로 기록하나 — git 으로는 구분이 안 된다

이 저장소의 **모든 커밋 작성자가 `pioneer3 <vrmaker65@gmail.com>` 하나**다.
팀원들이 같은 폴더(`/Users/pioneer3/project2608`)를 공유하고, 커밋은 저장소 로컬 git 설정을
따라가기 때문이다. 따라서 `git log --author` 로는 누가 무엇을 했는지 알 수 없다.

```bash
# 이 명령은 이 프로젝트에서 아무것도 구분해 주지 못한다
git log --author="..."          # 전부 pioneer3
```

**대신 각 노트북(세션)의 대화 이력을 근거로 삼는다.** 팀장 조성기가 팀원들에게
각 세션에서 작성자가 누구인지 밝히도록 지시해 두었고, **2026-09-01 이후 각 노트북에서
팀원이 이름을 입력하기로 했다.** 그 시점부터는 세션 단위로 기여가 구분된다.

## 어느 노트북이 누구인가 — 기기 대조표

팀원 4명이 각자 노트북으로 작업하므로, 세션이 시작되면 훅이 기기를 자동 식별한다.

- 대조표: [기기-대조표.md](./기기-대조표.md) — 기기 ID(`sha256(MAC)` 앞 8자) ↔ 팀원
- 확인 명령: `bash scripts/JSG-machine-id.sh`
- **원본 MAC 주소는 저장하지 않는다.** 해시 앞 8자와 기기 이름만 남긴다
- 기기 ID 는 기기를 가리킬 뿐이다. **최종 귀속은 세션에서 본인이 밝힌 이름**을 따른다

## 파일 규칙

- 팀원 한 명당 파일 하나: `docs/작업기록/<팀원명>.md`
- 세션 첫머리에 본인을 밝히면, 그 세션에서 한 작업을 해당 파일에 쌓는다
- **확실한 것만 귀속한다.** 다른 세션에서 이루어진 작업은 "이 세션 밖"으로 분리하고
  본인 확인을 받는다 — 잘못 귀속하는 것이 비어 있는 것보다 나쁘다

## 문서 구성

각 파일은 아래 순서를 따른다.

```markdown
# 작업 기록 — <팀원명>
**기간** / **근거**

## 한눈에            표 하나로 영역별 요약
## 1..N              영역별 상세 (지시한 것 · 판단한 것 · 결과)
## 귀속 근거          이 세션 밖 작업을 명시하고 확인 요청
```

**"지시한 것"과 "판단한 것"을 나눠 적는다.** 선택지를 받아 고른 결정은 그 팀원의 판단이므로
따로 드러낸다 — 발표에서 기여를 설명할 때 이 부분이 실질이다.

## 앞으로의 제안

워크트리나 클론을 나눌 때 팀원별로 git 작성자를 다르게 두면 다음부터는 자동 집계된다.

```bash
git config user.name  "<팀원명>"
git config user.email "<본인 메일>"
```

기존 커밋은 소급되지 않으므로, 지금까지의 기여는 이 폴더의 기록이 유일한 근거다.
