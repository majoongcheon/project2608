# 정규화 튜닝 실험 기록

**작성** 오현근 세션 · 2026-09-02
**브랜치** `experiment/HG-model`
**결론** **채택하지 않는다.** 성능 이득은 통계적 근거가 부족하고(폴드 하나에 의존),
안정성은 오히려 나빠진다. L1 도 목적(소수 표본 억제)을 달성하지 못했다.

> 이 문서는 실험 순서대로 쓰였다. 4~7장은 **중간 관찰**이고,
> 8~10장의 폴드별 편차와 L1 검증을 거쳐 결론이 뒤집혔다.
> 바쁘면 **10장부터** 읽으면 된다.

---

## 0. 쉽게 요약

### 무엇을 해봤나

모델에 **브레이크를 걸어 봤다.**

모델은 학습 데이터를 보고 "이 답을 한 사람은 부담이 크더라" 같은 규칙을 만든다. 그런데
너무 열심히 외우면 새로운 사람에게는 오히려 틀린다. 기출문제만 외운 학생 같은 것이다.
**정규화**는 "요점만 잡아라"라고 강제하는 브레이크다.

브레이크에는 두 종류가 있다.

- **L2** — 모든 규칙을 조금씩 약하게 만든다
- **L1** — 쓸모없는 규칙을 아예 지운다

### 왜 해봤나

문제가 하나 있었다.

> 퇴사 이유 문항에서 **딱 3명이 고른 선택지**가 판정에 큰 영향을 주고 있었다.

세 명의 답이 전체 판정을 흔드는 것은 위험하다. 그 세 명이 우연히 그렇게 답했을 뿐일 수도
있으니까. **L1 브레이크가 이런 규칙을 지워줄 것**으로 기대했다.

### 무엇이 나왔나

**① 브레이크를 풀었더니 성적이 조금 올랐다** — 예상과 반대였다.

성적(macro F1)이 0.338 에서 0.359 로 올랐다. 그런데 자세히 보니 믿을 만하지 않았다.

데이터를 다섯 조각으로 나눠 다섯 번 시험하는데(교차검증), **조각마다 성적이 0.30~0.37 로
들쭉날쭉**했다. 올랐다는 0.02 는 그 흔들림보다 작다. 게다가 **다섯 조각 중 한 조각에서만
크게 좋았고**, 그것을 빼면 차이가 거의 사라졌다.

**② 브레이크를 풀면 그 3명짜리 규칙이 오히려 두 배로 커졌다.**

성적이 오르는 방향과, 안정성이 좋아지는 방향이 **정반대**였다.

**③ L1 은 기대한 일을 하지 않았다.**

L1 이 규칙 절반을 지운 것은 맞다. 그런데 **적게 답한 것을 골라 지우는 게 아니었다.**

| | 지워진 비율 |
|---|---|
| 10명 이하가 고른 선택지 | 25% |
| 200명 넘게 고른 선택지 | 4% |

적게 답한 쪽이 좀 더 많이 지워지긴 했지만, **3명짜리 중에도 살아남아 오히려 커진 것이
있었다.** L1 은 "적게 답한 것"이 아니라 **"설명력이 약한 것"** 을 지운다. 적게 답했어도
그 답이 결과를 잘 설명하면 살려 둔다.

### 결론

**지금 설정을 그대로 둔다.** 얻는 것은 불확실하고 잃는 것은 확실하다.

### 그래도 얻은 것

- **"정규화도 해봤다"는 근거**가 생겼다 — 15개 조합을 시험했고 기록이 남았다
- **소수 표본 문제는 정규화로 못 푼다**는 것을 알았다. 다른 방법을 찾아야 한다
  (선택지 묶기, 또는 그 문항 빼기)
- 코드가 정리됐다 — 세 곳에 흩어져 있던 설정이 한 곳으로 모였다

## 1. 왜 했나

지금 모델은 정규화가 **기본값 그대로**였다.

```python
LogisticRegression(max_iter=2000, random_state=SEED)   # penalty='l2', C=1.0
```

한 번도 조정해 본 적이 없어, 어제 정리한 다음 시도 목록의 ①번이었다.

**기대했던 것** — 분석에서 이런 걸 찾았다.

> 5번 문항(퇴사 이유)의 한 선택지는 **6명** 응답으로 계수가 +1.345 다.
> 소수 표본이 계수를 크게 흔든다. (`HG_모델-데이터-분석-v1.0.0.md`)

L1 정규화가 그런 계수를 0으로 눌러 **모델을 안정시켜 줄 것**으로 봤다.
성능 자체는 과적합이 없어서(train 0.3704 vs test 0.3416) 크게 안 오를 것으로 예상했다.

**결과는 예상과 반대였다.** 아래 4장 참조.

## 2. 코드 변경

### 문제 — 같은 설정이 세 곳에 흩어져 있었다

```
stages/_core.py:103    LogisticRegression(max_iter=2000, random_state=SEED)
stages/export.py:63    LogisticRegression(max_iter=2000, random_state=config.SEED)
stages/evaluate.py:28  LogisticRegression(max_iter=2000, random_state=config.SEED)
```

한 곳만 고치면 갈라진다.

### 고친 것 — 한 곳으로 모으고 손잡이를 달았다

`ml/cb_burden/stages/_core.py`

```python
# 로지스틱 기본값 — **지금 배포본을 만든 값이다.** 바꾸면 다른 모델이 나온다.
LOGIT_DEFAULTS = {'penalty': 'l2', 'C': 1.0, 'max_iter': 2000}

def make_logit(**over):
    p = dict(LOGIT_DEFAULTS)
    p.update({k: v for k, v in over.items() if v is not None})
    solver = p.pop('solver', None)
    if solver is None:
        solver = 'saga' if p['penalty'] in ('l1', 'elasticnet') else 'lbfgs'
    return LogisticRegression(solver=solver, random_state=SEED, **p)
```

`solver` 를 자동으로 고른다 — **`lbfgs` 는 L1·elasticnet 을 풀지 못한다.**
이걸 안 하면 sklearn 이 오류를 낸다.

`cv_scores`·`export.run`·`evaluate.run` 에 `logit_params` 인자를 더했다.
**주지 않으면 기본값**이므로 지금 동작이 그대로다.

### 안전장치

`ml/tests/test_logit_params.py` 5건을 먼저 썼다.

| 테스트 | 잡는 것 |
|---|---|
| 기본값이 지금 배포본과 같다 | `penalty='l2'` · `C=1.0` · `max_iter=2000` · `solver='lbfgs'` |
| 세기를 바꿀 수 있다 | `C` 만 바뀌고 나머지는 유지 |
| L1 은 solver 를 알아서 바꾼다 | `saga` 로 전환 |
| elasticnet 도 받는다 | `l1_ratio` 전달 |
| None 을 주면 기본값 | 호출부가 `None` 을 넘겨도 안전 |

**전체 테스트 75건 통과.** 골든 3,000건도 그대로라 기본 동작이 안 바뀐 것이 확인된다.

## 5. 중간 판단 — 보류 (8~10장에서 최종 결론)

| # | 이유 |
|---|---|
| 1 | **교차검증 값일 뿐이다.** test 602건으로 확인해야 진짜인데, test 는 한 번만 써야 해서 신중해야 한다 |
| 2 | **+0.02 가 잡음일 수 있다.** 5-fold 의 **폴드별 편차를 아직 안 봤다.** 폴드마다 ±0.02 씩 흔들린다면 의미 없는 차이다 |
| 3 | **안정성이 나빠진다.** 3명짜리 계수가 두 배가 된다. 다음에 데이터를 새로 받으면 그 3명이 바뀌면서 계수가 크게 흔들린다 |
| 4 | 발표에서 "소수 표본이 결과를 흔든다"는 지적을 받으면 **답하기 어려워진다** |

## 6. 중간 판단 — L1 이 대안일까 (9장에서 기각된다)

`l1 C=1.0` 은 눈여겨볼 만하다.

```
macro F1 0.3392  (지금 0.3383 과 거의 같음)
재현율   0.7498  (지금 0.7843 보다 낮음 — SC-005 관점에서 손해)
계수 0   56.2%   (절반 이상을 눌렀다)
```

**성능을 유지하면서 계수 절반을 0으로 만든다.** 안정성만 놓고 보면 이쪽이 낫다.
다만 재현율이 0.035 떨어지는데, 이 서비스에서 재현율은 가장 비싼 지표다.

`C` 를 1.0~3.0 사이에서 더 훑어보면 **재현율을 지키면서 계수를 누르는 지점**이 있을 수 있다.

## 8. 폴드별 편차 — +0.02 가 진짜인가

평균만 보면 안 된다. 5개 폴드가 각각 얼마나 흔들리는지 봤다.
**비교를 공정하게 하려고 결정 가중치를 배포본 값으로 고정**했다.

### macro F1

| 설정 | 폴드1 | 폴드2 | 폴드3 | 폴드4 | 폴드5 | 평균 | 표준편차 |
|---|---|---|---|---|---|---|---|
| l2 C=1.0 (지금) | 0.3321 | 0.3148 | 0.3632 | 0.3725 | 0.2995 | 0.3364 | ±0.0311 |
| **l2 C=10** | 0.3527 | 0.3191 | 0.3593 | 0.3851 | 0.3659 | **0.3564** | ±0.0241 |
| l1 C=1.0 | 0.3291 | 0.3197 | 0.3736 | 0.3615 | 0.3012 | 0.3370 | ±0.0299 |

**폴드 간 편차(±0.031)가 두 설정의 차이(+0.020)보다 크다.**

### 짝지어 비교

같은 폴드끼리 빼면 폴드 자체의 난이도가 상쇄돼 더 예민하게 볼 수 있다.

```
폴드별 차이(C=10 − C=1):  +0.0206  +0.0043  −0.0039  +0.0126  +0.0664
평균 +0.0200 · 표준편차 ±0.0275
5개 중 C=10 이 이긴 횟수: 4/5
평균차이 / 표준오차 = 1.63
```

| 관점 | 해석 |
|---|---|
| 4/5 승 | 방향은 일관된다 |
| **1.63** | **2에 못 미친다** — "우연이 아니다"라고 말하기 부족하다 |
| 폴드5 의 +0.0664 | **한 폴드가 평균을 끌어올렸다.** 빼면 평균 +0.0084 로 떨어진다 |

**폴드 하나에 기댄 결과다.** 5개 폴드로는 이 이상 가릴 수 없다.

### L1 은 명확히 동점

```
폴드별 차이(L1 − C=1):  −0.0030  +0.0049  +0.0104  −0.0110  +0.0017
평균 +0.0006 · 이긴 횟수 3/5
```

> **앞선 4.1 표의 정정** — 그리드에서 L1 재현율이 0.7498 로 낮게 나온 것은
> **결정 가중치를 매번 다시 탐색했기 때문**이다. 배포본 가중치로 고정해 공정하게 비교하면
> **0.7882 로 지금(0.7844)보다 오히려 높다.** 앞 표의 재현율 열은 이 점을 감안해 읽어야 한다.

## 9. L1 이 정말 소수 표본을 눌렀는가 ★

애초에 정규화를 시도한 목적이 이것이었다. 응답자가 적은 선택지부터 확인했다.

| 문항 | 값 | 응답자 | 지금(l2) | L1 | 결과 |
|---|---|---|---|---|---|
| 일과 만족 | 해당없음 | 3명 | 0.294 | **0.000** | 0 으로 눌림 |
| 가족 지지 | 해당없음 | 3명 | 0.876 | 1.059 | **커짐** |
| 퇴사 이유 | 15 | 3명 | 0.598 | 0.076 | 줄어듦 |
| 퇴사 이유 | 14 | 4명 | 0.305 | **0.000** | 0 으로 눌림 |
| 퇴사 이유 | 11 | 5명 | 0.546 | 0.148 | 줄어듦 |

## 10. 결론 — 정규화 튜닝은 채택하지 않는다

| 후보 | 성능 | 안정성 | 판단 |
|---|---|---|---|
| **l2 C=10** | +0.0200 (근거 부족, 1.63) | **나빠짐** — 3명짜리 계수 2배 | **기각** |
| **l1 C=1.0** | +0.0006 (동점) | **목적 미달** — 소수 표본을 골라 누르지 못함 | **기각** |
| l2 C=1.0 (지금) | 기준 | 기준 | **유지** |

**얻는 것이 불확실하고 잃는 것이 확실하다.** 지금 설정을 유지한다.

### 그래도 남은 것

1. **`make_logit()` 이 생겼다** — 세 곳에 흩어져 있던 설정이 한 곳으로 모였고,
   앞으로 어떤 실험이든 인자만 넘기면 된다. 테스트 5건이 기본값을 지킨다
2. **"정규화도 해봤다"가 근거로 남았다** — 15개 조합 + 폴드별 편차 + 소수 표본 추적
3. **L1 의 성질을 알게 됐다** — 표본 크기가 아니라 설명력으로 자른다.
   소수 표본 문제는 정규화로 풀 수 없다

### 소수 표본 문제는 다른 방법이 필요하다

정규화로는 안 된다는 것이 확인됐으니, 필요하다면 이런 방법을 봐야 한다.

- **선택지 병합** — 응답 10명 이하 선택지를 "기타"로 묶는다
- **문항 제거** — 5번(퇴사 이유)은 결측 88.1% 이고 재현율 손실이 −0.008 뿐이었다

둘 다 **모델이 아니라 데이터 표현을 바꾸는 것**이다.
