## 1.2 학습 — 모델을 만드는 과정

### Input

| | 내용 |
|---|---|
| 데이터 | `data/snapshots/cb_dataset_2026-09-01.csv.gz` · 3,000행 · 38변수 |
| 무결성 | sha256 로 고정. 학습 시작 때 다시 계산해 대조 |
| 분할 | train 2,398 / test 602 · `cv_fold` 1~5 사전 배정 |
| 목표변수 | `care_burden` — **1이 최고부담인 역방향 척도** |
| 제외 | FR-004b 배제 6변수는 입력에 없음 (검사로 강제) |

### Process — 네 단계

```
① baseline    38변수 전체로 계열 3종 비교 (logit · rf · et)
                 각 계열마다 5-fold 교차검증 + 결정 가중치 탐색
                 → 재현율 하한을 넘는 것 중 F1 최고인 계열 채택

② select      후진 제거 — 가장 덜 중요한 변수를 하나씩 뺀다
                 뺄 때마다 교차검증. 성공 기준을 못 넘으면 중단
                 → 38개 → 7개에서 멈춤 (6개는 미달)

③ calibrate   판정 불가 임계값을 데이터로 도출
                 확신도·희소성 격자를 훑어 두 조건을 만족하는 최소 비율
                   · 판정 불가 ≤ 10%
                   · 판정 불가군 오분류율 > 판정군 오분류율
                 → tau_conf 0.3239 · tau_dens -2.4343

④ export      아티팩트 6종 + joblib 생성
```

**test 602건은 여기서 쓰이지 않습니다.** 전 단계가 train 2,398건의 교차검증만 씁니다.

### Output

```
models/runs/<실행시각_커밋>/
├── model_v1.json          계수 5×53 · 절편 · 범주 · 결정 가중치
├── uncertainty_v1.json    tau_conf · tau_dens · 응답 빈도표
├── questions_v1.json      7문항 텍스트 · 선택지
├── selection_v1.json      선별 33단계 이력
├── contribution_v1.json   기여 요인 강약 기준 0.13250
├── golden_v1.json         3,000건 정답 확률 (회귀 방지용)
├── model_v1.joblib        sklearn 객체 그대로 ← 서비스가 읽는 것
└── run.json               스냅샷 해시 · git 커밋 · 라이브러리 버전 · 성공 기준
```

**배포본(`models/*.json`)은 건드리지 않습니다.** 쓰기 경로가 `runs/` 하나뿐입니다.

## 1.3 배포 — 승격

### Input

### Process — 다섯 관문. 하나라도 걸리면 아무것도 안 바뀝니다

```
① 필수 파일 확인      model_v1.json · golden_v1.json

③ 성공 기준 확인      SC-004 · SC-005 · SC-016 전부 PASS
④ 아티팩트 검증       스키마 · features 순서 · 문항 순서 ·
                     척도 방향([1,2,3,4,5]) · 임계값 범위 · 버전 일치
⑤ 릴리스 중복 확인    이미 있으면 거부 (릴리스는 불변)
```

### Output
```
models/v1.0.0/        릴리스 (불변)
models/current.json   { "release": "v1.0.0", "promoted_at": "…" }
```

## 1.4 서비스 — 진단 한 번

### Input

```json
POST /api/v1/diagnoses
{ "answers": [ {"questionNo":1,"value":4}, … 7개 ],
  "careTargetAge": 20,
  "location": { "lat": …, "lng": … } }
```

`value: null` 은 "해당사항 없음" → 결측 센티널 `-1` 로 변환

### Process

```
[Node 백엔드]
 ① 미응답 확인                     있으면 422 로 돌려보냄 (FR-007)
 ② 설정에서 판정 기준 읽기          tau_conf · tau_dens · 결정 가중치 · 기여 임계값
 ③ 유닉스 소켓으로 파이썬에 전달     답변 + 기준을 함께
        │
        ▼
[파이썬 추론]
 ④ 원-핫 인코딩 → predict_proba    확률 5개
 ⑤ 희소성 계산                     응답 조합이 학습 분포에서 얼마나 드문가
 ⑥ 판정 불가 판단                  희소성 < 기준 → sparse
                                   최대확률 < 기준 → ambiguous
 ⑦ 판정되면 구간 결정               확률 × 결정 가중치의 최대
 ⑧ 기여 요인 분해                  판정된 구간 기준 상위 3개
        │
        ▼
[Node 백엔드]
 ⑨ 표시 명칭 붙이기                내부 라벨 1~5 → "최고부담군" 등
 ⑩ 참조 집단 비교 (DB)             같은 구간 비율 · 같은 응답 비율
 ⑪ 기관 연계 (DB)                  반경 10→20→50km 로 넓히며 최대 3곳
 ⑫ 동의 시 학습용 저장              취소 토큰 발급
 ⑬ 내부 라벨 제거                  응답에 숫자를 넣지 않음 (FR-010a)
```

### Output

```json
{ "decided": true,
  "burdenLabel": "중간부담군",
  "burdenDescription": "…",
  "contributions": [ {"text":"… — \"도움이 필요하지 않음\"", "isMinor":false}, …3개 ],
  "comparison": [ {"text":"전국 조사에서 …%", …}, …4개 ],
  "immediateReferral": { "facilities": [ …3곳 ] },
  "cancelToken": "…", "disclaimer": "…" }
```

**세 갈래로 갈립니다.**

| 경우 | 나가는 것 |
|---|---|
| 판정 성립 | 구간 + 기여 요인 + 비교 (+ 고부담이면 기관 안내) |
| **판정 불가** | 구간 없음 + 판정 불가 안내 + **기관 안내** |
| **추론 서비스 장애** | 구간 없음 + 장애 안내 + **기관 안내** |

뒤의 둘은 다릅니다 — 판정 불가는 모델이 답을 못 하는 것이고, 장애는 물어보지 못한 것입니다.
