## 계획에서 바꾼 것 — 스위치 기본값

계획은 `diagnosisService` 를 HTTP 호출로 **교체**하는 것이었다. 그대로 하면 코드가 올라가는
순간 판정 경로가 바뀐다. 오늘 오전 사고를 생각해 **스위치를 두고 기본값을 기존 동작으로** 했다.

```
CB_INFERENCE=ts    (기본) 내장 계산 — 코드만 올라와도 판정이 바뀌지 않는다
CB_INFERENCE=http        파이썬 추론 서비스
```

되돌리기가 환경변수 하나이고, **배포와 전환을 분리**할 수 있다.
검증을 마친 뒤 운영을 `http` 로 넘겼다(아래 참조).

## 가장 중대한 발견 — 기여 요인이 다른 구간 기준으로 계산됐다

`saabas.contributions(model, row, cls=None)` 는 `cls` 를 주지 않으면 **아티팩트의 결정
가중치**로 구간을 다시 고른다. 그런데 엔진은 **설정에서 온 정책 가중치**로 구간을 골랐다.

두 가중치가 다르면 **화면에 표시된 구간과 그 아래 설명이 서로 다른 구간 기준**이 된다.
"고부담군입니다" 라고 해 놓고 중간부담군 기준의 기여 요인을 보여주는 셈이다.

정책을 설정으로 옮기기로 한 이번 설계에서 **새로 생긴 위험**이었다. 재현 테스트를 먼저 쓰고
고쳤다.

```python
# ★ cls 를 반드시 넘긴다. 생략하면 saabas 가 아티팩트의 결정 가중치로 구간을 다시 고른다.
contrib, _base = saabas_contributions(self.model_json, [float(v) for v in row], cls_idx)
```

`test_기여요인은_실제로_판정된_구간_기준이다` 로 고정했다.

## 포트를 쓰지 않는 통신으로 전환

팀에 배정된 포트는 **프론트 9503 · 백엔드 9523 두 개뿐**이다. 추론 서비스에 9533 을
새로 쓰려던 것을 **유닉스 도메인 소켓**으로 바꿨다.

```
[Vue :9503] ── [Node :9523] ──run/cb-inference.sock──▶ [파이썬 추론]
```

| 얻은 것 | 내용 |
|---|---|
| 포트 소비 | **0개** — 파일로 통신한다 |
| 외부 노출 | **불가능** — 네트워크에 열리지 않는다. nginx 설정도 그대로 |
| 성능 | 로컬 소켓이라 TCP 보다 오히려 빠르다 |

Node 쪽은 `node:http` 의 `socketPath` 로 붙는다(표준 라이브러리, 새 의존성 없음).
전송 층을 주입 가능하게 만들어 테스트에서는 가짜를 넣는다 — 소켓 없이도 시험이 돈다.

**전환 후 재검증**

| 확인 | 결과 |
|---|---|
| 소켓 경로로 판정 200건 | 기대와 다른 판정 **0건** |
| 추론 서비스를 죽인 상태 | `unavailable` · 안내 · **기관 안내 3곳** · 문항 조회 200 |
| 되살린 뒤 | 자동으로 정상 판정 복귀 |
| 사용 중인 포트 | **9503 · 9523 두 개뿐** |

> 되살린 직후 한 번 `unavailable` 이 나왔다. **소켓 파일 존재만 확인하고 접속 가능 여부를
> 보지 않은 내 검증 절차의 문제**였다. `ECONNREFUSED` 는 그 순간의 정상 반응이고,
> 다음 요청부터 바로 정상이었다. 제품 결함이 아니다.

## B7 — TS 추론 제거 (완료)

**복구 지점** `7c2f9d4` — 두 경로가 모두 살아 있는 상태. 문제가 생기면 여기로 되돌린다.

**지운 것**

| 파일 | 역할 |
|---|---|
| `backend/src/inference/predictor.ts` | softmax·트리 순회·기여도 이식본 |
| `backend/src/inference/undecidable.ts` | 희소성·판정 불가 판단 이식본 |
| `backend/tests/parity/` | Python↔TS 대조 (대조할 대상이 사라졌다) |
| `package.json` 의 `test:parity` | 가리키는 곳이 없어졌다 |
| `CB_INFERENCE` 스위치 | 경로가 하나뿐이라 의미가 없다 |

**남긴 것**

`backend/src/inference/modelLoader.ts` 와 `types.ts` 는 남겼다. 계획은 "문항 로드와 DB
문항 대조만 남긴다" 였으나, 이 로더는 **기동 시 아티팩트 존재와 정합을 검사하는 관문**이다.
`uncertainty`·`contributionThreshold` 를 반환 값에서 빼는 것은 이득 없이 위험만 늘린다.

**검증**

| 확인 | 결과 |
|---|---|
| `tsc --noEmit` | 통과 |
| 테스트 | ml 65 · 백엔드 51 · 프론트 17 = **133건** (parity 5건이 골든으로 이관돼 줄었다) |
| 기동 | `추론 서비스 : unix:…/run/cb-inference.sock · v1.0.0` |
| 판정 200건 | 기대와 다른 판정 **0건** |
| 판정 성립 / 판정 불가 | 구간·기여요인 3·비교 4·연계까지 전과 동일 |

**이제 백엔드에 모델 계산 코드가 없다.** 모델을 바꿔도 파이썬만 고치면 된다.
