## 2. 신설이 필요한 슬라이드 여섯 장

### M1. 연구 목적 4분류 — "우리는 넷 중 무엇을 했나"

**위치** 슬라이드 2(왜 만들었나) 다음.
**왜 필요한가** 이 한 장이 있으면 발표 내내 따라붙는 질문 두 개가 미리 정리된다 —
*"그래서 원인이 뭔가요"* 와 *"정확도가 48%인데 쓸 수 있나요"*.

| 목적 | 했나 | 근거 |
|---|---|---|
| Summary | **했다** | 3,000가구 분포 · 고부담 54.3% |
| Relation Description | **했다** | 도움 필요 시간 r=+0.442 · 근로 의미 이해도 r=−0.429 |
| Causal Explanation | **하지 않았다** | 1회 횡단면 조사다. 종단·RCT·성향점수매칭이 없으면 인과를 말할 수 없다 |
| Prediction | **했다** | 7문항 → 5구간 · 고부담 재현율 0.773 |

기준 문서의 두 문장을 그대로 인용하면 좋다.
> **관계가 있다고 해서 인과관계가 있는 것은 아니다.**
> **예측을 잘한다고 해서 원인을 설명하는 것은 아니다.**

**발표 문장** — *"우리는 '왜 부담이 생기는가'를 답하지 않았습니다. 이 데이터로는 답할 수 없습니다.
우리가 답한 것은 '지금 어떤 상태인가'와 '이 응답이면 부담이 클 가능성이 얼마인가'입니다."*

> 이 한 장이 지금 슬라이드 17(말 걸기)·19(한계)에 흩어져 있는 겸손함을 **발표 앞머리로 끌어와
> 방법론 용어로 못 박는** 역할을 한다.

### M2. `(n, p)` — 표 한 장의 모양이 여덟 번 바뀐다

**위치** 슬라이드 3(데이터) 다음.
**왜 필요한가** PDF 전체의 척추다. 그리고 우리 값을 그대로 끼우면 **한 장으로 전처리 전체가 설명된다.**

| 단계 | 무엇을 만졌나 | 모양 변화 |
|---|---|---|
| 현상 → 표 | 개체=가구, 속성=문항 | ∅ → **(3,000, 45)** |
| 정제 | 무응답 코드를 NULL 로 통일 · 행은 한 건도 안 버림 | (3,000, 45) → **(3,000, 43)** |
| X / y 분리 | `care_burden`(I13)을 떼어낸다 | → **X(3,000, 38) + y(3,000, 1)** |
| **누수 배제** | target 과 같은 것을 재는 6열 제거 | 44 후보 → **38** |
| 분할 | target 층화 80:20 | → **train(2,398) + test(602)** |
| 변환 | 결측 −1 센티널 후 원-핫 | (2,398, 7) → **(2,398, 53)** |
| 축소 | 후진 제거 | 38변수 → **7문항** |
| 기법 | 다항 로지스틱 fit | X → f → ŷ |
| 평가 | 두 벡터 비교 | (y, ŷ) → macro F1 · 재현율 |

**핵심 문장(PDF 2장 그대로)** — *"기법은 이 사슬의 한 칸일 뿐, 나머지 일곱은 모두 데이터 조작이다."*

덧붙일 것 — PDF 3장의 **세 가지 결정**을 우리 사례로 답한다.
- 개체를 무엇으로 볼 것인가 → **보호자 1인(가구 1건)**
- 어떤 속성을 담을 것인가 → **38개** (여기서 천장이 정해졌다 — 슬라이드 5와 직결)
- 무엇을 맞힐 것인가 → **I13 돌봄부담 5구간** (역방향 척도)

### M3. 분할이 변환보다 먼저다 — 누수를 세 층에서 막았다

**위치** 슬라이드 4(누수 6변수) 바로 뒤. **지금 S4 는 3층 중 1층만 말한다.**

| 층 | 무엇을 | 우리 구현 |
|---|---|---|
| ① 설계 | 변수 자체를 뺀다 | 정답이 새는 6변수 배제 ← **지금 S4 가 이것만** |
| ② fold | 통계를 fold 학습 부분에서만 계산 | 원-핫 범주·결측 대체·표준화·클래스 가중치 전부 |
| ③ test | 마지막에 딱 한 번 | test 602건 · `cv_fold` 는 NULL |

**PDF 8장의 대비를 우리 사례로 바꿔 넣을 수 있다.**

| | PDF 예시 | 우리 실측 |
|---|---|---|
| 잘못 | 전체로 스케일러 fit → 교차검증 0.95 (거짓) | 클래스 가중치를 OOF 전체에서 고르고 **같은 OOF 에서 채점** |
| 옳음 | fold 학습 부분에서만 fit → 0.88 (진짜) | fold **안쪽 3겹 CV** 에서만 고름 |
| 차이 | −0.07 | macro F1 **0.3383 → 0.3348** |

> **우리가 직접 그 함정에 빠졌다가 스스로 찾아냈다** 는 것이 이 슬라이드의 값어치다.
> 최호준이 09-02 오후에 기존 벤치마크의 채점 편향을 발견해 다시 측정했다.

여기에 PDF 7장의 **StratifiedKFold** 이유도 들어간다 — 5등급이 77건뿐이라 단순 KFold 면
어떤 겹에는 5등급이 거의 안 들어가 macro F1 이 그 한 구간 때문에 요동친다.

### M4. Relation Description — 어떤 요인이 부담과 관련되는가

**위치** 슬라이드 4(누수) 다음, 슬라이드 5(48%) 앞.
**왜 필요한가** md §3 이 요구하는 단계인데 **발표에 통째로 없다.** 지금 S4 의 MI/H 순위는
*문항을 고르기 위한* 지표지 *관계를 기술하는* 지표가 아니다.

이미 측정돼 있는 값 (`HG_라벨품질-점검.md`, train 2,398건 스피어만):

| 변수 | r | 읽으면 (1이 최고부담인 역방향 척도) |
|---|---|---|
| `help_needed_hours` | **+0.442** | 도움이 많이 필요할수록 부담이 크다 |
| `understands_work_meaning` | **−0.429** | 이해하지 못할수록 부담이 크다 |
| `can_work_standard_job` | −0.396 | 통상근로가 어려울수록 부담이 크다 |
| `overall_health` | +0.270 | 건강이 나쁠수록 부담이 크다 |
| `family_support_for_employment` | +0.247 | 가족 지지가 낮을수록 부담이 크다 |
| `daily_routine_satisfaction` | +0.241 | 당사자가 일과를 싫어할수록 부담이 크다 |

`|r| ≥ 0.20` 이 38개 중 8개, `|r| ≥ 0.10` 이 18개.

**그리고 방향을 코드북과 대조했다** — 배포 문항 4개의 선택지 문구를 직접 확인해
**네 개 모두 상식과 같은 방향**임을 확인했다. 라벨이 무작위로 붙었다면 나올 수 없는 결과다.

**반드시 함께 적을 것 (md §3 "중요한 점")** — *"관계가 발견되었다고 해서 원인이라고 말할 수 없다."*
슬라이드 안에 이 문장을 두면 M1 과 짝이 맞는다.

### M5. Clustering → Profiling — 우리 데이터의 보호자 유형

**위치** 슬라이드 5(48%는 모델 탓이 아니다) 바로 뒤.
**왜 필요한가** md §9 는 클러스터링의 목적을 *"응답자 안에 어떤 유형의 집단이 존재하는지
발견하는 것"* 이라 하고 유형 A/B/C 예시를 든다. **우리 발표는 군집화를 "구조가 없다"는
부정 근거로만 쓰고 유형을 보여주지 않는다.** 그런데 프로파일은 이미 뽑혀 있다.

`notebooks/HG-실험-군집화.ipynb` 의 k=5 결과 (train 2,398건, y 를 빼고 38변수만 사용):

| 군집 | n | 고부담(1+2) | 옆모습 |
|---|---|---|---|
| **4** | 558 | **80.7%** | 보호자 최고령(61.4세) · 가족 지지 최저(2.30) · 만성질환 최다(5.02) · 당사자 미취업 |
| 1 | 516 | 53.3% | 보호자 최연소(54.0세) · 장애 의심 시점 이름 |
| 3 | 219 | 51.6% | 퇴사 이유 응답이 뚜렷(6.22) · 학교 도움 큼 |
| 0 | 397 | 49.7% | 장애 의심 시점 늦음(10.17) · 가구주 유형 이질적(4.35) |
| **2** | 708 | **37.8%** | **당사자가 유일하게 취업 상태(1.07)** · 가족 지지 최고(4.48) · 저부담군 비율 21.9% |
| 전체 | 2,398 | 54.3% | — |

**md §9 의 유형 예시와 대응시켜 말할 수 있다.**
- 군집 4 ≈ **유형 A/B 혼합형** — 지원 필요도 높고 사회적 지지 낮고 보호자 건강이 나쁘다
- 군집 2 ≈ **유형 C 상대적 안정형** — 사회적 지지 충분, 당사자 취업, 부담 수준 낮음

**두 가지를 반드시 함께 적는다.**
1. **군집은 부담으로 갈리지 않았다** — ARI 0.027. 갈린 축은 **취업 여부·생애 단계·보호자 건강**이다.
   그런데 그 축이 결과적으로 고부담 비율을 37.8% ~ 80.7% 로 갈랐다.
2. **PDF 11장의 함정 그대로** — *"실루엣 계수는 잘 뭉쳤나를 잴 뿐 의미 있게 나뉘었나는 못 잰다."*
   우리 실루엣은 전 구간 0.25 미만(최고 k=2 에서 0.1233)이다. 그래서 이 프로파일은
   **"발견된 유형"이지 "검증된 유형"이 아니다.** 이 단서를 빼면 과대 해석이 된다.

> **이 슬라이드가 M4(관계)와 M1(인과 안 함) 사이를 잇는다.**
> 군집 4 의 축(보호자 고령·만성질환)은 **7문항에 없다** — 슬라이드 19 한계와 바로 연결된다.

### M6. 재현성과 활용 — PDF 12장

### R1. 슬라이드 6 — "세 후보" 를 실제 규모로

지금 표는 **다항 로지스틱 / 랜덤 포레스트 / 엑스트라 트리 3종**이다. 실제로는 —

| 실험 | 규모 | 결과 |
|---|---|---|
| 신지현 벤치마크 | 단일 7종 + 앙상블 4종 = **11구성** × 2문항셋 | 7문항·38변수 **양쪽 다 로지스틱 1등** |
| 최호준 재측정 | 단일 5종 + 앙상블 4종, 5회 반복 CV + 부트스트랩 2,000회 | **이긴 구성 0개** |

**PDF 11장의 표(기법별 데이터에 하는 일과 스케일 요구)를 한 열로 붙이면 방법론과 맞물린다.**

| 기법 | 데이터에 하는 일 | 스케일 | 우리 결과 |
|---|---|---|---|
| 로지스틱 회귀 | 하나의 직선·평면으로 가른다 | 필요 | **채택** |
| 랜덤포레스트·부스팅 | 축에 수직으로 자른다 · 다수결 | 불필요 | 전부 아래 |
| K-평균·PCA | 중심점 · 분산이 큰 방향 | 필요 | 구조 확인용 |

**왜 단순한 쪽이 이겼는지**도 PDF 용어로 말할 수 있다 — 3,000건에 5클래스, 그중 5등급이 61건뿐이라
상호작용을 배우기엔 표본이 얇다. 그리고 부수 효과로 **기여 요인이 근사가 아니라 정확히 분해**된다.

### R3. 슬라이드 12 — 평가 함정을 명시한다

PDF 11장이 경고하는 두 함정을 **우리가 실제로 겪었다.**

| 함정 | 우리 사례 |
|---|---|
| **불균형이면 정확도에 속는다** | 스태킹은 5구간 정확도만 0.4754 로 가장 높은데(로지스틱 0.4199) 고부담 재현율은 더 낮다. **정확도로 골랐다면 잘못 골랐다** |
| **실루엣은 잘 뭉쳤나만 잰다** | 실루엣 0.1233 은 "구조가 없다" 는 말이지 "유형이 없다" 는 말이 아니다 (M5) |

여기에 우리가 **정확도를 성공 기준으로 삼지 않은 이유**를 한 문장으로 적으면 슬라이드 12 가 완성된다.
