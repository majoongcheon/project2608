## 1. 데이터 분할 구조 (Split & Fold)

모델의 객관적인 평가와 재현성 확보를 위해 **층화 80:20 분할**과 **train 내부 층화 5-fold**를 데이터베이스 내 컬럼으로 고정하여 물리적으로 관리합니다.

* **전체 데이터 수**: 3,000건
* **분할 방식**: Target 변수(`care_burden`, 1~5 척도)의 분포 비율을 보존하는 층화 추출(Stratified Sampling)
* **무작위성 통제**: 행 내용 MD5 해시(`row_key`) 순서 기반 고정 분할

### 분할 상세 (split / cv_fold)

| 구분 | 컬럼 값 | 건수 | 비율 | 설명 및 용도 |
|---|---|---|---|---|
| **Train 데이터** | `split = 'train'` | **2,398건** | 79.93% | 모델 학습 및 교차 검증용 |
| └ **CV Fold 1~5** | `cv_fold = 1~5` | 각 ~480건 | (Train 내 20%씩) | Train 내부 층화 5-fold 교차검증 (튜닝 및 모델 선택) |
| **Test 데이터** | `split = 'test'` | **602건** | 20.07% | 최종 모델 성능 평가용 (`cv_fold`는 `NULL`) |

## 3. 전처리 및 특징 공학(Feature Engineering) 파이프라인 책임 분담

교차검증(CV) 중 **Data Leakage(데이터 누수)**를 방지하기 위해 SQL 뷰와 Python 파이프라인의 역할을 엄격히 분리합니다.

* **SQL 뷰의 역할**:
  * Data Leakage 변수 제외 (38개 설명변수 정립)
  * 문자열 및 관례적 무응답 코드 정규화 (`NULL` 통일)
  * 분할 상태(`split`, `cv_fold`) 고정 및 제공
* **Python 파이프라인 책임**:
  * **연속형 결측치 대치**: 전체 데이터 통계가 아닌, 각 Fold 학습(Train) 부분의 통계량(중앙값 등)으로 대치
  * **One-Hot Encoding 및 Scaling**: Fold별 통계를 기준으로 파이프라인 내부에서 수행
