# 실험 기록 — 문항 수를 늘리면 나아지는가, 판정 불가는 왜 뜨는가

**기간**: 2026-09-01 오후
**결론**: **7문항(v1.0.0)을 유지한다.** 14문항은 성능 이득이 없고 판정 불가만 늘었다.
**관련 문서**: `docs/모델-학습-방법.md` · `notebooks/모델-학습-과정.ipynb`

---

## 0. 왜 시작했나

문항 선별 규칙이 뽑은 값은 **k=7** 이었다. 그런데 7문항으로 "당신은 고부담군입니다"라는
결과를 내밀면 **보호자가 신뢰하기 어렵다**는 판단이 있었다. 성능이 크게 나빠지지 않는다면
문항을 늘려 납득성을 높이자는 것이 출발점이다.

두 가지를 시험했다.

| 실험 | 내용 | 결과 |
|---|---|---|
| **A** | 문항을 14개로 늘린다 (`v1.1.0`) | 성능 동일, **판정 불가 1.7배 증가** → 되돌림 |
| **B** | 나이 변수를 구간화한다 (`v1.2.0`) | 판정 불가 **변화 없음**, 재현율 하락 → 채택 안 함 |

---

## 1. 실험 A — 문항을 7개에서 14개로

### 방법

후진 제거 경로에서 정지 지점을 `K_TARGET=14`로 지정했다. 규칙(정지 조건)은 그대로 두고
멈추는 지점만 사람이 바꾼 것이다. 가중치 튜닝에는 손대지 않았고, 튜너가 k=14에서 스스로
1.1을 골랐다.

```bash
K_TARGET=14 MODELS_DIR=models/v1.1.0 MODEL_VERSION=v1.1.0 QSET_VERSION=qs-v1.1.0 \
  python3 ml/train.py build
```

### 결과 — 성능은 같고 판정 불가만 늘었다

| | 7문항 `v1.0.0` | 14문항 `v1.1.0` |
|---|---|---|
| macro F1 (CV) | 0.3383 | 0.3319 |
| macro F1 (**test**) | 0.3416 | **0.3420** |
| 고부담 재현율 (CV) | 0.7843 | 0.7559 |
| 고부담 재현율 (**test**) | **0.7730** | 0.7669 |
| **판정 불가 (test)** | **2.49%** | **4.20%** |
| 원-핫 열 수 | 53 | 224 |
| SC-004·005·016 | 전부 PASS | 전부 PASS |

**성능은 사실상 같다.** test macro F1 차이 0.0004는 잡음이고, 재현율은 7문항이 오히려
0.006 높다. 반면 **판정 불가가 2.49% → 4.20%로 1.7배 늘었다.**

즉 문항을 두 배로 늘려 **보호자의 응답 부담은 늘리고, 결과를 못 받는 사람은 더 늘렸으며,
정확도는 얻지 못했다.**

### 왜 판정 불가가 늘었나

7문항에는 나이 변수가 하나도 없었는데, 14문항에는 두 개가 들어왔다.

| 변수 | 레벨 수 | 평균 log p |
|---|---|---|
| `caregiver_age` 보호자 나이 | **78** | **−3.782** |
| `age_disability_suspected` 장애 의심 나이 | **60** | **−2.703** |
| 나머지 12개 문항 | 4~16 | −0.47 ~ −1.59 |

`rarity`(응답 조합이 학습 데이터에서 얼마나 흔한가)는 문항별 빈도의 로그 평균이다.
보호자 나이를 **한 살 단위 78개 범주**로 두면 "57세"인 사람은 학습 데이터의 1.3%뿐이라
`log(0.013) ≈ −4.3`이 된다. 이 두 변수가 rarity 평균을 혼자 끌어내린다.

## 2. 실험 B — 나이를 구간으로 묶으면 판정 불가가 줄어드는가

### 가설

나이를 구간화하면 각 구간의 빈도가 10% 이상으로 올라가 rarity가 회복되고, 희소성으로 인한
판정 불가가 사라질 것이다. 덤으로 원-핫 열이 줄어 과적합도 완화될 것이다.

구간은 train 분포에서 각 구간이 최소 3% 이상 되도록 잡았다(`ml/bins.py`).

```
caregiver_age             8구간   39세 이하 / 40~49 / 50~54 / 55~59 / 60~64 / 65~69 / 70~79 / 80 이상
age_disability_suspected  5구간   만 2세 이전 / 3~5 / 6~9 / 10~14 / 15세 이후
```

### 결과 — **가설의 절반만 맞았다**

| | v1.1.0 (나이 원본) | v1.2.0 (구간화) |
|---|---|---|
| `age_disability_suspected` 평균 log p | −2.703 | **−1.421** |
| 전체 평균 rarity | −1.466 | **−1.239** |
| 원-핫 열 수 | 224 | **100** |
| **판정 불가 (CV)** | **3.0%** | **3.0%** |
| macro F1 (CV) | 0.3319 | 0.3316 |
| 고부담 재현율 (CV) | 0.7559 | **0.7437** |

**희소성 지표는 크게 개선됐는데 판정 불가 비율은 조금도 안 줄었다.**

원인은 **임계값이 자동으로 따라오기 때문**이다. 보정 단계(`stage_calibrate`)는
"SC-016을 만족하는 조합 중 발생률이 가장 낮은 지점"을 격자 탐색으로 찾는다. rarity 분포가
위로 올라가면 `τ_dens`도 같이 올라와(−2.5354 → −2.3525) 결국 같은 비율에 안착한다.

> **판정 불가 3%는 데이터에서 나온 값이 아니라 보정 규칙이 겨냥한 목표값이다.**
> 모델을 어떻게 바꾸든 train 기준 비율은 3% 근처에 머문다. 바뀌는 것은 **test·운영에서의
> 비율**뿐이다.

그리고 구간화로 `caregiver_age`의 설명력이 떨어져 **후진 제거에서 탈락**했다.
채택 문항이 바뀌었다.

```
빠짐   : caregiver_age(보호자 나이), employment_status(근무 형태)
들어옴 : can_work_standard_job(통상근로 가능 여부), primary_caregiver_type(주 보호자 유형)
```

`v1.2.0`은 test 평가를 하지 않았다. CV에서 재현율이 떨어졌고 목적(판정 불가 감소)도
달성하지 못해, test를 한 번 더 여는 비용을 치를 이유가 없었다.

## 3. 판정 불가에 "가까운 구간"을 알려줄 수 있는가 — 없다

판정 불가일 때 구간을 감추는 대신 **"참고로 부담이 큰 쪽으로 보입니다"** 처럼 방향만
알려주는 안을 검토했다. 5구간 명칭보다 뭉갠 표현이니 덜 틀릴 것이라 보았다.

**실측 결과 이 전제가 틀렸다.**

| 집단 | n | 5구간 정확도 | 2단계(고부담 여부) 정확도 |
|---|---|---|---|
| 확신도 부족 | 48 | 0.333 | **0.542** |
| 희소성만 | 24 | 0.333 | **0.542** |
| 판정됨 | 2,326 | 0.430 | 0.672 |

기준선과 나란히 놓아야 뜻이 보인다.

```
무작위로 찍기                    0.500
아무에게나 "큰 쪽"이라 답하기      0.543   ← 학습 데이터의 고부담 비율
판정 불가 집단의 2단계 정확도       0.542
```

**모델을 쓰지 않고 모두에게 "큰 쪽"이라 말하는 것과 정확도가 같다.** 판정 불가로 분류된
사람에 대해 모델이 가진 정보가 사실상 없다는 뜻이다.

"2단계로 뭉개면 덜 틀린다"는 판단은 **기준선을 확인하지 않은 오판이었다.**
5구간 0.333 → 2단계 0.542는 선택지가 5개에서 2개로 줄어 우연히 맞을 확률이 오른 것일 뿐,
기준선 대비 이득은 0이다.

근거 없는 방향을 "참고"라는 이름으로 제시하면 절반은 반대 방향을 안내받는다.
헌법 원칙 I(근거 기반 판정)·II(정직한 불확실성)와 정면으로 부딪히므로 **채택하지 않는다.**

### 대신 가능한 것 (미구현)

판정 불가에도 **추측이 아닌 사실**은 알려줄 수 있다.

- **왜 어려운지** — 확신도 부족(2%)과 희소성(1%)은 원인이 다르므로 문구를 나눈다
- **무엇이 드물었는지** — 어느 문항의 응답이 드물었는지는 계산 가능하며 틀릴 수 없는 사실이다
- **응답 요약** — 판정은 못 해도 답한 내용은 되짚어 줄 수 있다

FR-009a가 "부담 구간과 기여 요인을 표시하지 않는다"고 정하고 있어 스펙 변경이 필요하다.

## 4. 결론

**7문항 `v1.0.0`을 유지한다.** 규칙이 뽑은 값이 옳았다.

| 근거 | |
|---|---|
| 성능 | test에서 14문항과 동등 (F1 0.3416 vs 0.3420, 재현율 0.7730 vs 0.7669) |
| 판정 불가 | **2.49% vs 4.20%** — 7문항이 유리 |
| 응답 부담 | 문항 절반 |
| 검증 | test 602건 평가 통과 (2026-09-01 11:51 기록) |

7문항이 적어 보인다는 우려는 유효하지만, **문항을 늘려도 정확도가 오르지 않는다는 것이
실측으로 확인됐다.** 납득성을 높이려면 문항 수가 아니라 **문항 문구와 결과 화면의 설명**을
개선하는 쪽이 맞다.

## 6. 이 실험에서 드러난 판단 착오

기록해 두지 않으면 반복된다.

- **test 평가 전에 배포했다.** `v1.1.0`을 공개 주소에 올린 뒤에 test 평가를 했다.
  문항 수를 정하는 중에 test를 열지 않은 것은 옳았으나, **확정한 시점과 배포 시점 사이에
  평가가 들어갔어야** 했다.
- **"구간화하면 판정 불가가 준다"고 예측했다.** 임계값이 자기 보정한다는 것을 계산에
  넣지 않았다.
- **"2단계로 뭉개면 덜 틀린다"고 권했다.** 기준선(0.543)을 확인하지 않았다.
- **문항 수를 늘리는 결정에 데이터 근거가 없었다.** k=14는 제품 판단이었고 그 자체로
  문제는 아니지만, **늘렸을 때 무엇이 나빠지는지(판정 불가)를 먼저 재보지 않았다.**
