### JSG-01 · 카카오 키 없이 지도 시각화

- **접수일**: 2026-09-01
- **분류**: 지도 / 화면
- **상태**: ✅ **반영 완료 (2026-09-01)**
- **관련**: FR-016(지도+목록), FR-017(기관 정보), FR-018(길찾기), research.md **R-7**,
  `frontend/src/components/MapView.vue`, `frontend/src/pages/MapPage.vue`, `frontend/.env.local`

**원문**

> \# 의료기관 지도 시각화 중심좌표는 의료기관 위치의 평균 위도, 경도 값으로 설정
>
> ```python
> pharmacy_map = folium.Map(location=[dj_map_df['위도'].mean(),
>                                    dj_map_df['경도'].mean()],
>                          zoom_start=11)
>
> # 중심좌표 확인하기
> folium.Marker(location=[dj_map_df['위도'].mean(),
>                         dj_map_df['경도'].mean()],
>               ).add_to(pharmacy_map)
>
> # 의료기관 위치에 마커 추가하기
> for idx in dj_map_df.index:
>   popup_text = str(dj_map_df['약국명'][idx])
>   popup_text += '<br>' + str(dj_map_df['주소'][idx])
>
>   # 좌표값 추출하기
>   lat = dj_map_df['위도'][idx]
>   lng = dj_map_df['경도'][idx]
>
>   # 지도 추가하기
>   folium.Marker(location=[lat, lng],
>                 icon= folium.Icon(color='blue', icon='plus-sign'),  # icon 설정
>                 popup= folium.Popup(popup_text, max_width=300)).add_to(pharmacy_map) # popup width 설정
>
> pharmacy_map
> ```
>
> 이런식으로 지도에 표시하는 방식을 참고해서 카카오키가 필요없이 지도로 시각화 하도록 구성하고 싶어.

**추가 지시 (2026-09-01)**

> 중심좌표는 기본적으로 현재 위치 또는 선택 지역의 대표좌표로 하고 싶어.

---

**확정된 요건**

| 항목 | 결정 |
|---|---|
| 지도 라이브러리 | **키가 필요 없는 방식**으로 교체 (Leaflet + OpenStreetMap — folium 의 실체) |
| 중심좌표 | **현재 위치, 없으면 선택 지역의 대표 좌표** — 예시의 마커 평균은 쓰지 않는다 |
| 마커 | 기관 위치마다 하나 |
| 팝업 | 예시를 따라 **기관명 + 주소**. 여기에 이용 대상 조건·거리·전화를 더할지는 구현 시 판단 |
| 길찾기(FR-018) | 영향 없음 — 지금도 `map.kakao.com/link/search/` 링크라 키를 쓰지 않는다 |

**중심좌표가 현행 유지인 이유** — 예시 코드는 `mean()` 으로 마커 무게중심을 잡지만,
이 서비스의 지도는 "내 주변에서 가까운 곳"을 보여주는 것이 목적이라 기준점이 **보호자 위치**여야
한다. 현재 구현이 이미 그렇게 되어 있으므로(`MapPage.computed center` → 좌표 우선, 없으면
`cb_region_v1.center_lat/lng`) **이 부분은 바꾸지 않는다.** 다만 마커가 화면 밖으로 나가지 않도록
현재 쓰는 `setBounds` 를 유지할지, 고정 줌(예시의 `zoom_start=11`)으로 바꿀지는 구현 시 정한다.

**메모** (내가 확인한 사실 — 원문과 섞지 않는다)

- 예시의 `folium` 은 내부적으로 **Leaflet + OpenStreetMap 타일**을 쓴다. 키가 없는 이유가
  여기 있다. 우리 런타임은 Vue/TS 라 folium 을 그대로 쓸 수는 없고, **Leaflet 을 직접 쓰면
  같은 결과**가 된다(마커·팝업·중심좌표 개념이 1:1 대응).
- **이 요청은 research.md R-7 의 결정을 뒤집는다.** R-7 은 Kakao 를 채택하며 Leaflet+OSM 을
  "국내 상세 주소·건물 정보가 부족해 FR-017 품질을 못 맞춘다"는 이유로 기각했다.
- 뒤집어도 되는 근거는 있다 — 기관 좌표 1,283건이 **이미 DB 에 확보**되어 있어(결측 0건)
  지오코딩이 필요 없다. 지도의 역할이 "이미 아는 좌표에 마커를 찍는 것"뿐이라면 OSM 타일로
  충분하고, R-7 이 걱정한 주소 검색 품질은 쟁점이 되지 않는다. **종합 시 R-7 을 갱신해야 한다.**
- 예상 변경 범위: `MapView.vue` 교체, `leaflet` 의존성 추가, `VITE_KAKAO_MAP_KEY` 제거,
  `research.md R-7`·`quickstart.md`·`CLAUDE.md` 갱신. 백엔드·DB 변경 없음.
- **확인 필요**: OSM 타일 서버는 외부 CDN 이다. 폐쇄망·오프라인 시연 계획이 있으면 타일을
  못 받으므로 지금의 목록 폴백이 그대로 필요하다.
- 부수 효과 하나 — 키가 없어지면 `.env.local` 설정 없이도 지도가 뜬다. 지금은 키가 없어
  목록으로 폴백하는 상태라, 이 요청이 반영되면 **시연 준비가 단순해진다.**

### JSG-02 · 학습 이용 동의 문항이 강요처럼 느껴짐

- **접수일**: 2026-09-01
- **분류**: 화면·문구 / 개인정보 흐름
- **상태**: 접수
- **관련**: FR-033(동의), FR-008a·c·e(자가보고 문항), FR-002a(사전 입력), SC-019(사전 입력 통과율),
  `frontend/src/pages/ConsentPage.vue`, `frontend/src/pages/PreSurveyPage.vue`,
  `frontend/src/pages/SurveyPage.vue`

**원문**

> 현재 설문이 끝나고 학습에 사용할건지 물어보는 문항이 팝업으로 뜨는데 화면을 너무 가리는 느낌이라
> 반드시 눌러라라고 강요하는 듯한 기분이 들었어. 팝업하지 않고 하단에 표시하거나 처음 화면의
> 사용자 정보 입력할때 하단에 같이 선택하도록 수정하는 방향이면 좋겠어.

---

**메모** (내가 확인한 사실 — 원문과 섞지 않는다)

**사실 확인 — 팝업은 아니다.** `ConsentPage.vue` 는 모달이 아니라 독립 라우트
(`/diagnosis/consent`)다. `position:fixed`·오버레이·`z-index`·`backdrop` 어느 것도 쓰지 않는다.
설문 마지막 문항에서 `router.push('/diagnosis/consent')` 로 화면이 통째로 바뀐다.

**그러나 "강요당하는 느낌"은 정확한 지적이다.** 원인은 팝업이 아니라 아래 코드다.

```ts
const canSubmit = computed(() =>
  consent.value === false || (consent.value === true && selfReport.value !== null));
```

동의/미동의 **둘 중 하나를 반드시 고르기 전에는 "결과 보기" 버튼이 비활성화**된다.
설문을 다 마친 사람 앞을 가로막는 전면 화면이라, 형태가 팝업이 아니어도 체감은 같다.
**고쳐야 할 대상은 팝업이 아니라 이 강제 관문이다.**

**제안하신 두 방향의 검토**

| 방향 | 명세 적합성 | 비고 |
|---|---|---|
| (a) 팝업 없이 **하단 표시** | 가능 | 마지막 문항 화면 하단에 동의를 두고, 동의 시 자가보고 문항을 같은 화면에서 펼친다 |
| (b) **사전 입력 화면**에서 함께 선택 | 가능 · 명세와 더 잘 맞음 | 아래 참조 |

**(b) 를 택할 때의 구조** — 명세 제약을 모두 만족한다.

```
사전 입력   별명 · 대상자 연령 · 돌봄 대상 수 · [학습 이용 동의]   ← 전부 선택 사항
   ↓
설문 7문항
   ↓
자가보고 부담 문항  ← 동의한 경우에만 (FR-008e)
   ↓
제출 → 결과
```

- FR-033 "제출 전 고지·동의" → 사전 입력은 제출보다 앞이므로 만족
- FR-008e "동의 고지가 자가보고 문항보다 앞" → 만족
- FR-008c "자가보고는 결과 표시 전" → 자가보고는 설문 뒤에 그대로 남으므로 만족
- **동의와 자가보고가 분리된다.** 지금은 한 화면에 붙어 있어 동의가 자가보고의 관문처럼 보인다

**강제 관문을 없애는 방법** — 동의를 **미선택 상태로 넘어갈 수 있게** 하고 미선택을 미동의로
처리하면 된다. FR-033 은 "동의를 받아야 저장한다"이지 "선택을 강요하라"가 아니므로,
미선택 = 미동의 = 저장 안 함 으로 두는 편이 오히려 명세 취지에 맞다.
사전 입력의 다른 세 항목이 모두 선택 사항인 것과도 일관된다(FR-002a).

**주의할 위험 두 가지**

1. **SC-019 초기 이탈** — 사전 입력 화면 도달자의 95% 이상이 첫 문항까지 진행해야 한다.
   항목이 3개 → 4개로 늘면 이탈이 늘 수 있다. spec Risks 의 "사전 입력에 따른 초기 이탈"과
   같은 문제다. 동의를 눈에 띄지 않게 배치하고 건너뛰기를 분명히 해야 한다.
2. **동의율 변화** — spec Risks 는 동의율을 **성공 기준으로 두지 않기로** 했다(합격선을 걸면
   동의를 유도하려는 화면 설계 압력이 생겨 "거부해도 불이익 없음"과 충돌하기 때문).
   위치를 옮기면 동의율이 달라질 수 있으므로 `cb_event_log_v1.consent_training` 으로
   전후를 관측하되, **동의율을 올리는 방향으로 설계를 조정하지 않는다.**

**예상 변경 범위** — `PreSurveyPage.vue`(동의 항목 추가), `SurveyPage.vue`(마지막에 자가보고
문항 편입), `ConsentPage.vue`(제거 또는 축소), `router/index.ts`, `preSurveyStore.ts`.
백엔드·DB·모델 변경 없음. `POST /diagnoses` 의 `consentTraining`·`selfReportLevel` 계약은 그대로다.

**미결 질문**

1. (a) 하단 표시와 (b) 사전 입력 이동 중 어느 쪽인가? — 둘 다 가능하나 결과가 꽤 다르다
2. 동의를 미선택으로 넘어갈 수 있게 할 것인가? (권장: 예 — 강요 느낌의 실제 원인)

## JSG-01 반영 결과 (2026-09-01)

| 항목 | 결과 |
|---|---|
| 지도 라이브러리 | Kakao Maps SDK → **Leaflet 1.9.4 + OpenStreetMap**. 발급 키 불필요 |
| 중심좌표 | **기준 위치**(현재 위치 → 없으면 선택 지역 대표 좌표). 마커 평균 아님 |
| 기준 위치 마커 | 흰 배경 + 굵은 테두리로 기관 마커와 구분 (예시의 중심 확인 마커에 대응) |
| 기관 마커 | 기관마다 하나. 팝업 = **기관명 + 주소**(+ 직선거리) |
| 줌 | 검색 반경에 맞춰 자동(`zoomForRadius`) |
| 길찾기(FR-018) | 변경 없음 — 키 없는 링크 방식 그대로 |
