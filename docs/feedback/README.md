# 수정 요청 모음

팀원별로 수정 요청을 따로 쌓아 두었다가, 모인 뒤 한 번에 반영한다.
**이 폴더의 내용은 아직 구현하지 않는다.** 반영 시점은 별도로 결정한다.

## 파일 규칙

- 팀원 한 명당 파일 하나: `docs/feedback/<팀원명>.md`
- 소속이 불분명한 요청은 `docs/feedback/_미분류.md` 에 두고 나중에 옮긴다
- 항목 ID는 `<팀원 이니셜>-01` 형식으로 파일 안에서만 유일하면 된다

## 항목 형식

각 요청은 아래 네 가지를 갖는다. 원문을 그대로 남기는 것이 가장 중요하다 —
요약하면 나중에 의도를 되살릴 수 없다.

```markdown
### KDH-01 · 결과 화면 문구 조정
- **원문**: (팀원이 말한 그대로. 손대지 않는다)
- **분류**: 진단 / 지도 / 연계 / 데이터·모델 / 화면·문구 / 배포·운영 / 기타
- **관련**: FR-0xx, 파일 경로 등 (알면 적고, 모르면 비운다)
- **상태**: 접수 / 검토됨 / 반영 / 보류 / 반려
- **메모**: 내가 확인한 사실이나 충돌 여부 (원문과 섞지 않는다)
```

## 종합할 때 확인할 것

1. **서로 충돌하는 요청** — 같은 화면·문구를 다르게 바꾸자는 요청이 있는지
2. **명세와 충돌하는 요청** — `spec.md` 의 FR 이나 헌법 원칙과 어긋나는지
   (특히 개인정보 원칙 III, 판정 근거 원칙 I 은 요청보다 우선한다)
3. **모델 재학습이 필요한 요청** — 문항 변경은 `python3 ml/train.py all` 재실행과
   패리티 테스트 재통과가 따라온다
4. **반영 순서** — 데이터·모델 → 백엔드 → 프론트 순으로 묶어야 재작업이 적다
