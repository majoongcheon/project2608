# 곁 — 돌봄부담 진단 모델 `v1.0.0` (제출 패키지)

발달장애인 보호자를 위한 **경량 돌봄부담 자가 진단** 모델과 그 실행 코드.

**예측은 이 폴더만으로 재현할 수 있다.** 전체 과정(데이터 연결 → 준비 → 학습 → 서비스)을
담은 `최종-전체과정.ipynb` 만 저장소 전체가 필요하다 — §7 참조.

> 목적은 정확한 등급 산출이 아니라 **지원이 필요한 보호자를 놓치지 않고 안내로 잇는 것**이다.

---

## 1. 문제 정의

발달장애인 보호자는 돌봄 부담을 혼자 안고 가기 쉽고, **이용할 수 있는 지원이 있다는
사실조차 모르는 경우**가 많다. 기존 부담 척도는 문항이 30개 이상이라 진입 장벽이 높다.

```
① 7문항으로 부담 수준을 가늠한다        30문항 척도 → 후진 제거로 7문항
② 결과에 따라 신청처를 바로 안내한다     전국 875개 기관 · 시군구 221곳
```

### 설계에서 양보하지 않은 것

| 원칙 | 구현 |
|---|---|
| **모를 때는 모른다고 한다** | 확신이 낮거나 응답이 드물면 등급을 내지 않는다. 대신 기관 안내는 계속 나간다 |
| **놓치는 쪽이 더 비싸다** | 고부담 확률에 가중치를 둬 재현율을 우선한다 (77.3%) |
| **개인 식별 정보를 보관하지 않는다** | 모델 입력은 설문 응답 코드뿐이다. `predict()` 는 입력을 저장하지 않는다 |
| **근거 없는 값을 못박지 않는다** | 문항 수·판정 불가 임계값을 스펙에 적지 않고 **학습 데이터에서 도출**한다 |

한계와 금지 사항은 [`model_card.md`](model_card.md) — 특히 **§6 사용 금지 상황**.

## 2. 이 폴더의 구조

```
model.joblib          Pipeline(OneHotEncoder → LogisticRegression)   전처리 + 확률
schema.json           입력 문항 · 타입 · 허용 범위 · 결측 규칙
policy.json           결정 가중치 · 판정 불가 임계값 · 빈도표 · 기여도 기준
predict.py            predict(payload) -> dict                       ← 진입점
model_card.md         용도 · 성능 · 한계 · 사용 금지 상황
README.md             이 파일
최종-전체과정.ipynb     데이터 연결 → 준비 → 학습 → 서비스 전 과정  (저장소 필요 · §7)
```

앞의 여섯은 이 폴더만으로 돌아간다. 노트북 하나만 예외다.

### 왜 파일이 나뉘어 있나

`Pipeline` 은 **전처리와 확률까지만** 담을 수 있다. 이 서비스의 판정은 그 뒤에 셋을 더 한다.

```
① 전처리 · 확률        model.joblib  (Pipeline)
② 판정 불가 판단        policy.json 의 임계값 · 빈도표
③ 결정 가중치 적용      policy.json 의 decision_weights
④ 기여 요인 계산        policy.json 의 expected_contrib + Pipeline 의 계수

predict.py 가 ①~④를 순서대로 엮는다.
```

> ⚠️ **`model.joblib` 만 단독으로 쓰면 안 된다.** `pipe.predict()` 는 ②③이 빠진 답을 낸다 —
> 등급이 3.54% 달라지고, 자신 없는 경우에도 등급이 그대로 나온다
> (실서비스 기준 결과 화면의 33.6%가 판정 불가였다).
> **운영과 같은 판정을 얻으려면 `predict.py` 의 `predict()` 를 쓴다.**

## 3. 실행 방법

### 준비 — 버전을 맞춘다

`joblib` 은 **만든 sklearn 과 읽는 sklearn 이 같아야 한다.** 다르면 경고만 나오고
결과가 조용히 달라질 수 있어, 버전을 못박는다.

```bash
python3 -m venv venv && source venv/bin/activate
pip install numpy==2.0.2 scipy==1.13.1 scikit-learn==1.6.1 joblib==1.5.3
```

**검증된 환경** — 아래 두 곳에서 이 폴더만 떼어내 실행했고 **출력이 바이트 단위로 같았다.**

| 파이썬 | 결과 |
|---|---|
| 3.9.6 (macOS 시스템) | 통과 |
| 3.11.7 | 통과 |

DB·네트워크를 쓰지 않는다. 이 폴더의 파일만 읽는다.

### 예측

```python
from predict import predict

result = predict({"answers": [
    {"questionNo": 1, "value": 4},     # 하루 일과를 어떻게 느끼나
    {"questionNo": 2, "value": 4},     # 가족의 취업 지지
    {"questionNo": 3, "value": 5},     # 하루 중 필요한 도움의 양
    {"questionNo": 4, "value": 1},     # 가구주 유형
    {"questionNo": 5, "value": None},  # 마지막 퇴사 사유 — "해당 없음"
    {"questionNo": 6, "value": 3},     # 당사자와의 관계
    {"questionNo": 7, "value": 1},     # 일의 의미 이해도
]})
```

명령줄에서도 된다.

```bash
python3 predict.py                       # 예시 응답으로 실행
python3 predict.py '{"answers": [...]}'  # JSON 을 직접 넘김
```

### 출력

```json
{ "modelVersion": "v1.0.0", "questionSetVersion": "qs-v1.0.0",
  "proba": [0.0193, 0.2077, 0.4295, 0.2875, 0.0560],
  "decided": true,
  "internalLabel": 3,
  "maxProba": 0.4295, "rarity": -1.1383, "undecidableReason": null,
  "contributions": [
    {"feature": "family_support_for_employment", "value": 4.0,
     "contrib": 0.242, "isMinor": false}, ...] }
```

판정하지 못한 경우에는 **구간도 기여 요인도 내지 않는다.**

```json
{ "decided": false, "internalLabel": null, "contributions": null,
  "undecidableReason": "sparse" }     // 또는 "ambiguous"
```

### ★ 척도 방향 — 가장 실수하기 쉬운 지점

**`internalLabel` 은 1이 최고부담, 5가 부담 없음인 역방향 척도다.**
숫자가 작을수록 부담이 크므로 임계값 비교는 `<=` 다.

| `internalLabel` | 표시 명칭 | 경고 | 즉시 안내 |
|---|---|---|---|
| 1 | 최고부담군 | O | O (+상담 강조) |
| 2 | 고부담군 | O | O |
| 3 · 4 · 5 | 중간부담군 · 저부담군 · 부담 없음 | X | X |
| `null` (판정 불가) | **표시하지 않음** | X | **O** (구분 문구 필수) |

**내부 라벨을 이용자 화면에 그대로 노출하지 않는다.** 표시 명칭만 낸다.

### 입력 규칙

`schema.json` 이 정의한다. 7문항이 **모두** 있어야 하고, 값은 각 문항의 `enum` 안이어야 한다.

| 표기 | 의미 | 허용 문항 |
|---|---|---|
| `value: <정수>` | 선택지 값 | 각 문항의 `enum` |
| `value: null` | "해당 없음" | `nullable: true` (5번) |
| `value: -1` | 결측 센티널 | `acceptsSentinel: true` (1·2·5번) |

`-1` 직접 입력은 **학습 데이터를 재현할 때만** 쓴다. 1·2번은 화면에 선택지가 없어
실서비스에서는 나오지 않는 값이다.

검증에 걸리면 `InvalidPayload` 예외가 난다.

```
응답하지 않은 문항이 있습니다: [7]
문항 1 의 값 9 는 허용 범위 밖입니다 [1, 2, 3, 4, 5]
```

## 4. 이 모델이 서비스 안에서 놓이는 자리

```
┌─ 오프라인 학습 (배포 대상 아님) ─────────────────────────────────────────┐
│  실태조사 3,000행 ─→ 스냅샷(.csv.gz + sha256) ─→ 학습 4단계 ─→ 평가 ─→ 승격 │
│                     DB 를 읽는 유일한 지점        runs/ 에만 씀   test 1회  │
└──────────────────────────────────────────────┬─────────────────────────┘
                                               ▼
                                   배포 아티팩트  ← 이 폴더는 여기서 나왔다
                                   ┌───────────┴───────────┐
                                   ▼                       ▼
┌─ 서비스 ─────────────────────────────────────────────────────────────────┐
│  파이썬 추론 서비스  ◀─ 유닉스 소켓 ─▶  백엔드 :9523  ◀─▶  프론트 :9503      │
│  (판정 계산 전담)                      (조립·연계)         (화면)          │
└─────────────────────────────────────────────────────────────────────────┘
```

### 판정 요청 한 건

```
7문항 응답
  → 문항 집합 버전 대조 (어긋나면 409)
  → 미응답 검사 (있으면 422 + 문항 번호)
  → "해당 없음"(null) → -1 치환
  → 확률 · 희소성 · 판정 불가 · 기여 요인        ← predict() 가 하는 부분
  → 결과 조립: 표시 명칭 · 기여 요인 · 참조 비교
  → 즉시 연계: 부담=발동 · 연령=필터 · 거리=정렬   ← 판정 불가여도 발동
  → 내부 라벨 제거 후 응답
```

### 기술 스택 (전체 서비스)

| 영역 | 스택 |
|---|---|
| 프론트엔드 | Vue 3.4 · TypeScript 5 · Vite 5 · Pinia 2 · Leaflet(OpenStreetMap) |
| 백엔드 | Node.js 20 · Express 4 · TypeScript 5 · mysql2 3 |
| 데이터베이스 | MariaDB 12.1.2 |
| 오프라인 학습 | Python 3.9~3.11 · scikit-learn 1.6.1 (**배포 대상 아님**) |

Docker 를 쓰지 않는다. 프로젝트 폴더 안의 코드와 선언적 설정으로만 전개한다.

## 5. 데이터와 성능

| 항목 | 값 |
|---|---|
| 학습 데이터 | 2024 장애인 실태조사 3,000행 · 설명변수 38개 |
| 분할 | train 2,398 / test 602 · **층화** · train 만 5-fold |
| 등급 분포 | 1:464 · 2:1,165 · 3:916 · 4:378 · 5:77 → 고부담 54.3% |
| 결측 | 38변수 중 14개 · 전체 칸의 12.8% (**대치하지 않고 `-1` 로 학습**) |
| 스케일링 | **하지 않는다.** 전 변수 범주형 → 원-핫 53열 |

**결측을 채우지 않는 이유** — 여기서 결측은 "모름"이 아니라 **설문 분기**다.
취업 경험이 없으면 "왜 그만뒀나"를 묻지 않는다(88.2%). 채우면 없던 사실을 만들게 된다.

### 성능 (test 602건 · 단 한 번 평가)

```
macro F1        0.3416   (38변수 기준 모델 0.3616 · 손실 0.0200)
고부담 재현율    0.7730   (기준 모델 0.7638 · 이득 +0.0092)
판정 불가        2.49%
릴리스 게이트 4개 전부 통과
```

**5등급 세분화는 못 하지만, 서비스가 실제로 내리는 판단인 "고부담이냐"는 77% 잡아내고,
큰 실수는 하지 않으며(오류의 90%가 옆 등급), 자신 없을 때는 모른다고 말한다.**

숫자의 배경과 한계는 [`model_card.md`](model_card.md) §3·§5.

## 7. 전체 과정 노트북

`최종-전체과정.ipynb` 는 **모델을 만드는 과정 전체**를 실행한다. 예측만 하려면 필요 없다.

```
1. 데이터 연결   DB(선택) 확인 · 학습 입력은 지문으로 고정된 스냅샷
2. 데이터 준비   지문 대조 · 무결성 5검사 · 층화 확인 · 결측을 채우지 않는 이유
3. 모델 학습     4단계 실행 → 배포본과 계수 대조 (재현성 확인)
4. 평가         교차검증만. test 602건은 쓰지 않는다
5. 서비스        실제 판정 2건 — 판정 성립 / 판정 불가
6. 마무리        배포본 지문 재대조
```

### 실행에 필요한 것

이 노트북만 **저장소 전체**가 필요하다 — 학습 코드(`ml/cb_burden`), 배포 아티팩트(`models/`),
학습 입력 스냅샷(`data/snapshots/`) 을 읽기 때문이다.

```bash
pip install numpy==2.0.2 scipy==1.13.1 scikit-learn==1.6.1 joblib==1.5.3             pymysql nbformat nbconvert ipykernel
jupyter notebook deliverables/최종-전체과정.ipynb      # 또는 아래 헤드리스 검증
```

`pandas` · `matplotlib` 를 쓰지 않는다 — 클린 환경에서 폰트·버전으로 깨질 여지를 없앴다.

### 안전 규칙

| 규칙 | 어떻게 |
|---|---|
| 배포본을 바꾸지 않는다 | 시작·끝에서 `models/*.json` 6개의 sha256 을 대조. 다르면 중단 |
| `test` 602건을 쓰지 않는다 | `evaluate` 를 부르지 않는다. 최종 성능은 기록된 값을 인용 |
| 학습은 격리된 곳에만 | `models/runs/<run_id>/` 에만 쓴다. `promote` 를 부르지 않는다 |
| DB 가 없어도 완주한다 | 스냅샷으로 폴백하고, **어느 경로를 썼는지 출력한다** |

채점 환경을 재현해 보려면 환경변수로 강제할 수 있다.

```bash
CB_NO_DB=1 CB_NO_SERVICE=1  jupyter nbconvert --execute --to notebook \
    --ExecutePreprocessor.timeout=900 deliverables/최종-전체과정.ipynb
```
